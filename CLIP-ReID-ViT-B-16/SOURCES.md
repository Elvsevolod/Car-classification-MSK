## Предобучение и риск номера

Метод основан на OpenAI CLIP; опубликованный checkpoint дополнительно обучен
авторами на VeRi. Полный корпус базового CLIP не воспроизводим из этого проекта.
Мы не утверждаем, что во всех внешних обучающих изображениях номера скрыты,
и не гарантируем независимость исходного checkpoint от номера. При продвижении
кандидата нужен тот же парный аудит сплошной заливки, что и для OSNet.

Наше продолжение использует только organiser train.csv и точные BBox автомобиля.
Ни OCR, ни восстановление номера, ни отдельный детектор анонимизации не добавлены.

## Локальные адаптации

- Убраны прямые CUDA-вызовы; float32 на MPS/CPU/CUDA, без CUDA AMP.
- Инференс — только изображение, `NECK_FEAT=before`, L2 от конкатенации двух частей.
- Все наши ID-prompts и классификаторы создаются заново; source-ID не сопоставляются.
- Frozen prefix/suffix взяты из проверенного checkpoint. Для единственного шаблона
  `A photo of a X X X X vehicle.` EOT находится в позиции 11.
  Проверены upstream BPE IDs ASCII-шаблона:
  `[320,1125,539,320,343,343,343,343,5299,269]`, плюс SOT/EOT.
  Свободный текст не принимается, отдельный tokenizer/LLM не нужен.
- Stage 1: LR 3.5e-4, Adam, 60 эпох; явный 5-эпоховый warmup и cosine до 1e-6.
- Stage 2: LR 5e-6, Adam, 60 эпох; 10-эпоховый warmup и ×0.1 на 30/50.
  Это адаптация scheduler под современный PyTorch, не обещание побитового
  воспроизведения старого upstream CUDA/timm.
- Image batch **32 (8×4)** вместо upstream 64 (16×4), чтобы работать на локальном MPS.
  Camera-aware sampling и бюджет эпох по числу предъявлений; ID не идут в encoder.
- torchvision RandomErasing с random pixel fill вместо upstream timm реализации;
  все остальные базовые transform/normalization согласованы с VeRi config.
- Оценка — неизменённый evaluator организаторов, не upstream VeRi evaluator.

Поэтому локальные результаты нельзя выдавать за воспроизведение цифр статьи.
