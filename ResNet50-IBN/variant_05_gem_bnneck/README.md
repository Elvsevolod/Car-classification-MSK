# Вариант 5: ResNet50-IBN-a + GeM + BNNeck

## Статус

Обучение завершено: mean outer mAP@10 `0.272971 ± 0.017324` по трём seed.
Активная OSNet в MVP не изменена. Это архив исходного эксперимента.

Аудит выявил короткий бюджет (285 обновлений в финале), изменение LR horizon
при переносе best epoch и два одинаковых полных кадра в разных inner частях
(разные автомобили/BBox). Outer split по identity/точным кадрам чистый.
Следующий запуск с исправленным протоколом вынесен в
[`variant_06_controlled_training`](../variant_06_controlled_training/).
Описание ниже фиксирует исторический протокол, а не исправленную версию.

Это первый эксперимент этапа альтернативных backbone. Он меняет архитектуру,
но сохраняет победивший обучающий рецепт OSNet variant 2: `P=16`, `K=2`,
BNNeck, `CE + SupCon`, consistency loss, square resize и раздельные learning
rate encoder/head.

## Инициализация

Backbone начинается не со случайных весов, а с официального ImageNet checkpoint
`resnet50_ibn_a-d9d0bb7b.pth` из
[XingangPan/IBN-Net v1.0](https://github.com/XingangPan/IBN-Net). При скачивании
PyTorch проверяет hash-префикс из имени файла, а полный SHA-256 записывается в
каждый итоговый отчёт.

Проверенный полный SHA-256 официального файла:
`d9d0bb7b2ba34d7e6e12c4616c9d233914762e49fbb9fcb49d7f4d65da6f759c`.

Это публичные воспроизводимые веса, а не добавление внешнего сырого датасета.
В обучении и подборе параметров используются только строки `dataset/train.csv`.
Test query/gallery нигде не участвуют в подборе.

Особенности модели:

- IBN-a в первых трёх residual-stage;
- `last_stride=1`, чтобы сохранить больше пространственных деталей;
- learnable GeM с начальным `p=3`;
- BNNeck;
- эмбеддинг 2048-D вместо 512-D у OSNet.

Последний пункт означает примерно четырёхкратный рост памяти для векторов. Поэтому
даже при приросте метрик отдельно учитываются размер ONNX и latency.

## Исходный протокол (см. ограничения в статусе)

1. Внутри 925 outer-train identity создаётся фиксированный split 80/20.
2. На нём по 6 эпох сравниваются encoder LR `3e-5`, `6e-5`, `1e-4`.
3. Лучший LR и его best epoch замораживаются.
4. Конфигурация заново обучается на всех 925 train identity с тремя seed:
   `20260915`, `20260916`, `20260917`.
5. Для каждого seed reranking и порог отказа подбираются только на calibration;
   validation оценивается один раз.
6. Сравниваются среднее и стандартное отклонение, а не лучший одиночный seed.

Модель считается лучше активной OSNet, только если одновременно:

- mean mAP@10 выше `0.814689`;
- mean quality score выше `0.441322`;
- mean candidate score не ниже `0.747121 - 0.005`.

## Запуск

Из корня репозитория:

```bash
.venv/bin/python -m jupyter lab
```

Открыть `train_resnet50_ibn.ipynb` и выполнить `Run All`. Если доступен MPS,
он выбирается автоматически. Если не видны ни MPS, ни CUDA, ноутбук остановится
до обучения, чтобы случайно не запустить долгий эксперимент на CPU. Первый запуск требует интернет только для загрузки
официального checkpoint; затем используется кэш PyTorch.

Контролировать выполнение не требуется. История и `last.pt` сохраняются после
каждой эпохи: после прерывания повторный `Run All` продолжит незавершённый запуск,
а готовые запуски пропустит. В выводе показываются номер эпохи, оставшееся число
эпох, время эпохи, прошедшее время и ETA.

## Артефакты

- `results/screening_summary.json` — выбор learning rate на inner split;
- `results/final_comparison.json` — среднее и разброс по трём seed;
- `results/export_summary.json` — источник весов, checksum, ONNX parity, размер и latency;
- `weights/screening/**` — resumable screening checkpoint;
- `weights/final_seeds/**` — финальные checkpoint трёх seed;
- `weights/resnet50_ibn_stage5.onnx` — экспериментальный inference encoder.

Checkpoint и ONNX исключены из Git. Итоговые JSON остаются в репозитории после
завершения обучения и позволяют воспроизвести вывод о выборе модели.
