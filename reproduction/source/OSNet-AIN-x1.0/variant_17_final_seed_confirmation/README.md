## Задача и фиксированный бюджет

Первый final дал R1 79,896% против B0 78,752% reranked mAP@10, но 95% bootstrap-интервал
разницы включает ноль. Исторический MVP имеет 81,469%; замены MVP не было.
Проверяем, насколько результат зависит от случайности финального обучения.

| Seed | B0 208×208 | R1 256×256 |
|---|---|---|
| 20260915 | Готовый final, только чтение | Готовый final, только чтение |
| 20260916 | Новое обучение, 800 updates | Новое обучение, 800 updates |
| 20260917 | Новое обучение, 800 updates | Новое обучение, 800 updates |

Итого **четыре новых обучения / 3200 optimizer updates**. Горизонт LR остаётся 1700,
а не сокращается до 800. Seed, рецепты, preprocessing, разбиения, устройства и версии
библиотек наследуются из manifest завершённого запуска. Train — прежние 925 identity /
5717 изображений; calibration и validation в обучение не добавляются.
Первый seed заново не обучается, не копируется и не оценивается.

У первого финала два обучения суммарно заняли около 28 минут без полной стоимости
проверок и экспорта. Поэтому ориентир для четырёх новых — около часа обучения плюс
проверки, calibration/outer и ONNX; это не гарантия wall-clock времени.

## Порядок выполнения

1. Проверить все три фазы variant16, хеши исходников/данных/весов/отчётов и runtime.
   Исходный `prepare()` не вызывается, manifest и lock исходного run не перезаписываются.

4. Зафиксировать все четыре checkpoint в `final_selection.json` **до первой новой outer-оценки**.
5. Отдельно калибровать порог каждого encoder только на исходной calibration.

   Посчитать **среднее и sample SD по трём seed**, а также парные разницы R1−B0.

## Возобновление и проверки

После прерывания: **Restart Kernel → Run All**, без изменения настроек и исходников.
Готовые модели проверяются и не переобучаются. Незавершённый training-блок (до 200 updates)
повторяется с восстановлением optimizer. Прерванные оценка/экспорт могут повториться,
но обучение уже завершённой модели не повторяется.
Если checkpoint успел сохраниться, а `history.json` — нет, производная история
восстанавливается из `last.pt`. Произвольное расхождение истории блокирует продолжение;
веса и summary при таком восстановлении не меняются.

Оценка считается завершённой только после записи `evaluation_complete.json` с хешами
evaluation/thresholds/ONNX/bundle/export. Наличие одного `evaluation.json` недостаточно.
Итоговый `complete.json` проверяет все новые модели, отчёты и сводку перед повторным чтением.
Повторный полностью завершённый запуск не выполняет optimizer steps или inference.
Чужие активные runs 14–16 проверяются read-only; варианты17 сериализуются общей блокировкой.
Межверсионная проверка best-effort: не запускать старый и новый notebook одновременно.

Notebook восстанавливает число CPU threads и deterministic flag из исходного manifest.
В текущем источнике device=MPS, threads=8. Тихого перехода на CPU/CUDA нет; несовпадение
runtime блокирует продолжение. CPU-обучение дополнительно запрещено по умолчанию.
При несовпадении хеша не удалять старый manifest/receipt и не обходить ошибку.

## Ограничения интерпретации

Это проверка устойчивости **на уже просмотренной outer development validation**, а не новый
независимый тест: решение добавить два seed принято после первого final.
Три обучения не превращают одни и те же query в три независимых набора наблюдений.
SD по seed — не доверительный интервал; три seed недостаточны для сильных гарантий.
Исторический MVP выбирался по outer и имеет другую процедуру отбора.
F1 и TNR рассматриваются отдельно от ranking: выигрыш F1 не означает улучшение отказов.
Автоматические маски не подтверждены как plate-only. GPU parity/скорость здесь не проверяются.
