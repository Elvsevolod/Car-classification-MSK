# OSNet-AIN x1.0: HPO на автоматически замаскированных изображениях

Новый изолированный эксперимент на базе
`../variant_02_hpo_bnneck_supcon/train_osnet_hpo.ipynb`.
Основное обучение ещё **не запускалось**, метрик новой модели пока нет.

## Что запускать

Откройте **train_osnet_masked_hpo.ipynb** с ядром репозитория `.venv/bin/python`.
Все `RUN_*` по умолчанию `True`: достаточно **Restart Kernel → Run All**.
Не нужно заново обучать YOLO или менять исходный HPO-notebook.
Модель автоматически использует CUDA, затем MPS, иначе CPU. Подготовка масок
идёт на CPU; координаты кэшируются для всех последующих trials.
Окружение и локальные зависимости используются уже существующие; автоматических
установок, скачиваний, внешних датасетов и отправки данных нет.

## Изображения и маски

1. Читается исходный кадр и официальный bbox машины, учитывается EXIF.
2. Дообученный YOLO11n находит области анонимизации в кропе.
3. Замороженная политика из validation-калибровки: confidence=0.20,
   увеличение рамки на 10% с каждой стороны; координаты округляются наружу.
4. Все найденные рамки закрашиваются непрозрачным чёрным цветом.
5. Затем выполняются прежние resize 208×208, аугментации и нормализация OSNet.

Маски применяются к **каждой строке train.csv во всех нужных разделах**:
обучение, обе ветви consistency loss, inner validation, calibration,
query/gallery итоговой validation. Ручные рамки вместо предсказаний не
подмешиваются. Если YOLO ничего не нашёл, кроп остаётся без новой маски;
это не доказательство отсутствия анонимизации. Пропущенная запись кэша,
напротив, вызывает ошибку — незаметного переключения на исходный датасет нет.

На диске сохраняются только координаты в `results/cache/automatic_masks.json`.
Исходные фото не изменяются и не дублируются; маски накладываются в памяти.
В notebook есть превью до/после. Независимость от всех номерных/анонимизационных
признаков не гарантируется: детектор может пропускать области и закрывать лишнее.

## Обучение и оценка

- Stock OSNet ONNX как в исходном HPO, **не продолжение активных весов MVP**.
- Прежние P=16/K=2, camera-aware sampler, раздельный encoder/head LR.
- 16 Optuna trials × 8 эпох; MedianPruner не ранее четвёртой эпохи.
- Top-4 продолжаются до 20 эпох; top-2 заново обучаются до 30 эпох с тремя seed.
- Перебираются BNNeck, Triplet/SupCon, encoder LR, LR multiplier головы,
  weight decay, веса metric/consistency loss, Triplet margin.
- Победитель выбирается по среднему лучшему inner mAP@10 и заново обучается
  на всех 925 outer-train identity до 30 эпох.
- **В отличие от старого notebook, финальный development checkpoint выбирается
  по calibration**, а outer validation оценивается только после его фиксации.
  Calibration также используется для порога отказа, поэтому её показатели
  не являются независимой оценкой качества.
- Для итогового best_map.pt считаются raw и фиксированный streaming reranking
  20/3/0.5, порог каждого режима подбирается только на calibration.
- Формулы метрик и junk filtering — из официального evaluate.py.

Все 240 кропов detector train/val/holdout и связанные с ними идентичности/точные
кадры исключены из HPO-validation. При этом они могут входить в HPO-train.
Внутреннее разбиение примерно 80/20, группировка не разрывает общие кадры.
Оно отличается от прежнего HPO, поэтому старые и новые inner-метрики напрямую
несопоставимы. Внешнее разбиение сохраняется. test_query.csv/test_gallery.csv
не участвуют. Outer validation использовалась в прошлых экспериментах проекта:
результат нового запуска всё равно не является новым независимым тестом.

## Файлы и продолжение

- `results/protocol.json`: хеши исходных кадров, весов, калибровки, кода и split.
- `results/<RUN_NAME>/`: отдельная Optuna DB, история этапов, конфигурация,
  run_manifest.json; кэш масок связан с запуском контрольной суммой.
- `weights/<RUN_NAME>/`: отдельные checkpoint всех этапов.
- `weights/<RUN_NAME>/selected/best_map.pt`: лучшая эпоха по calibration.
- `weights/<RUN_NAME>/selected/osnet_masked_best_map.onnx`: экспорт с BNNeck,
  если он выбран; проверяется численное совпадение с PyTorch.
- `results/<RUN_NAME>/selected/history.json`: эпохи, loss, LR, время и
  **calibration**-метрики (историческое имя поля в записи — `validation`).
- `results/<RUN_NAME>/selected/summary.json`: результат обучения по calibration.
- `results/<RUN_NAME>/selected/evaluation.json`: итоговые raw/reranked показатели
  calibration/outer validation, пороги, экспорт, parity.

После прерывания оставьте RUN_NAME и параметры прежними. Маски досчитываются
с последнего сохранения. Завершённые trials не повторяются; оборванный trial
может быть заменён новым. Длинные этапы продолжаются с last.pt; точное
воспроизведение последовательности случайных аугментаций после перезапуска
не обещается. Не запускайте два ядра с одним RUN_NAME одновременно.
Для независимого нового исследования меняйте RUN_NAME. При смене входных данных,
масок, кода или бюджета старые результаты не переиспользуются молча.

Сохраняются last.pt и best_map.pt, а не полная копия модели каждой эпохи;
для анализа всех эпох достаточно history.json. Веса, SQLite и кэш координат
исключены из Git. Старые файлы автоматически не удаляются.

**ONNX не содержит YOLO и закрашивание.** При будущем подключении такой модели
понадобится тот же этап маскирования перед OSNet как для gallery, так и для query.
MVP, его индекс, пороги, старые веса и исходный notebook не переключаются.
Результаты нового обучения нужно сравнить отдельно; выигрыш не гарантирован.
