# v27: объединение после независимого реранкинга

Открой `search_late_fusion.ipynb` в прежнем research `.venv`: **Restart Kernel → Run All**.
Все настройки выставлены. Обучения, повторного encoder inference, GPU, интернета и лимита времени нет.
Используются прежние реальные эмбеддинги MVP512+R1_1536. Активный MVP v25 не изменяется.

## Что сравнивается

В v25 смешиваются признаки, затем строится общий граф. Здесь MVP и R1 независимо строят
графы одной и той же статической gallery и обрабатывают каждый query отдельно.
После этого объединяются расстояния или позиции изображений. Между query нет обмена информацией.

43 заранее фиксированных варианта:

- контроль v25: feature fusion 50/50, k1=20, k2=3, λ=0.50;
- 42 поздние смеси: 3 способа × 2 значения λ R1 × 7 весов;
- способы: среднее расстояние, взвешенный RRF с k=10 и k=60;
- λ R1: 0.50/0.75; λ MVP=0.50; оба графа k1=20, k2=3;
- доля R1: 10/25/40/50/60/75/90%.

Distance: `(1-w)*d_MVP + w*d_R1`, меньше — лучше; используются исходные нормированные
расстояния текущего реранкера, без подбора шкал по validation.
RRF: `(1-w)/(k+rank_MVP) + w/(k+rank_R1)`, больше — лучше; позиции начинаются с 1.
Каждая ветка ранжирует всю gallery, объединение выполняется ДО усечения top-10.
Равные оценки разрешаются стабильным порядком исходного gallery CSV.

RRF опирается на [Cormack, Clarke, Büttcher, SIGIR 2009](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf).
В работе использован k=60; наши веса и дополнительный k=10 — экспериментальные варианты.
Результаты статьи на текстовом поиске не доказывают выигрыш в Vehicle ReID.

Источники v22–v26 защищены checksums, их code/runs/веса/аннотации не изменяются.
Проверяются 10 разных gallery ID при каждом запросе, включая отказ. Evaluator и junk-правила прежние.
