# v28 — четыре направления одним Run All

Открой `run_multi_hypothesis.ipynb` в прежнем research `.venv`: **Restart Kernel → Run All**.
Все 57 конфигураций включены. Лимита времени, нового обучения, загрузок и переключения MVP нет.
Нужны исходные локальные изображения и завершённый `v27/runs/late_fusion_v1` вместе с его источниками.
Первым выполняется контроль текущего лучшего v25 (validation mAP 0.8289573904).

## Пакет

| Направление | Конфигурации | Что проверяем |
|---|---:|---|
| Контроль v25 | 1 | Прежний feature fusion 50/50 и граф 20/3/0.50 |
| Состав R1 | 24 | Три одиночных seed и три пары; общая доля R1 0.50/0.75; λ 0.50/0.75 |
| Power normalization | 6 | signed abs(x)^γ, γ=0.50/0.75/1.25; λ 0.50/0.75 |
| Gallery centering | 8 | Вычитание 0.25/0.50/0.75/1.00 от среднего gallery; λ 0.50/0.75 |
| Flip-TTA | 18 | MVP / R1 / обе ветки; доля flipped 0.25/0.50/0.75; λ 0.50/0.75 |

Всегда k1=20, k2=3. Кроме семейства состава R1, доли MVP/R1 остаются 50/50.
Power и center применяются отдельно к MVP512 и R1_1536 с повторной L2-нормализацией.
Center вычисляет среднее только по статической gallery конкретного протокола, не по query
и не по identity/camera. Это простая исследовательская гипотеза, не обученная whitening-модель.
В R1 seed-нумерация 0/1/2 соответствует порядку `members` защищённого исходного bundle.
Для состава каждый 512-блок нормируется отдельно, выбранные блоки объединяются равновесно.

Flip отражает горизонтально только исходный crop организаторов после его штатного preprocessing.
Новые bbox, детекция, OCR и маски не добавляются. И query, и gallery обрабатываются одинаково.
Смешиваются original/flipped признаки **одного и того же encoder**, не координаты разных seed.
Для всех 18 конфигураций flip-признаки извлекаются один раз на split. Сначала проверяется
совпадение обычного forward с прежним кэшем на одном батче, с прежним допуском v24, без его расширения.

Power inspired by [Perronnin, Sánchez, Mensink, ECCV 2010](https://europe.naverlabs.com/wp-content/uploads/2010/09/PSM10_0766.pdf).
В статье изучались Fisher vectors и γ≤1; перенос на OSNet и γ=1.25 — наши экспериментальные
предположения, не результат статьи и не обещание прироста. Это не реализация RootSIFT.

## Организаторы и честный выбор

- Вопросы 9–10: только текущий query и статическая gallery. Query expansion прямо запрещён — не реализован.
- Вопрос 10 разрешает TTA одного изображения. Статистика query, предыдущие ответы и query clustering не используются.
- Вопросы 8 и 16 допускают произвольную размерность и ансамбли. Дополнительных весов нет.
- Исходные train/validation, разметка и официальный evaluator не изменяются; top-10/junk прежние.
- **Кандидат, confidence и threshold всегда исходные full R1**, без flip/center/power/subset.
- Отбор — единый максимум mAP на calibration по всем 57 конфигурациям. При точном равенстве остаётся v25.
- На validation только v25 и один общий победитель, не четыре победителя семейств. Ни одного дополнительного подбора там нет.
- Неполный набор не даёт зафиксировать выбор. Уже наблюдавшиеся splits — development, не независимый hidden test.

Ранжирование оценивается отдельно от отказа. Любое новое качество появится только после запуска.
Предыдущие v26/v27 результаты не подменяются, их сетки не повторяются целиком. Нового local-head,
KD/K2, fine-tuning, внешних данных и дополнительных seeds в этом пакете нет.

## Сохранение и восстановление

Задачи последовательны. Видны семейство, номер конфигурации, mAP, время и прогресс TTA по изображениям.
TTA сохраняется атомарными блоками по 128 изображений с проверкой IDs, настроек и checksum.
После прерывания **Restart Kernel → Run All с тем же RUN_NAME** продолжает готовые блоки/задачи.
Ошибка одного опыта не отменяет независимые опыты. Повреждённые исходники/кэши — немедленная остановка.
Если ошибку устранили изменением кода, требуется новое имя запуска, а не смешивание версий.

Выход: `runs/multi_hypothesis_v1/REPORT.md`, `results.json`, `progress.json`, `tasks/*/error.json`.
Отчёт содержит отдельные итоги четырёх семейств и общий результат; при ошибке сохраняется частичный отчёт.

Validation-экспорт: submission.csv с десятью уникальными ID на каждый query, candidates.csv
побайтно прежний, embeddings.npy — реальные float32 признаки в порядке query→gallery.
Для обычных вариантов это исходные 2048 признаков. Для TTA-победителя — 4096:
original2048 + flipped2048; original и R1 candidate-блок не меняются. embedding_order.json
содержит точную схему и ranking specification. Повторное ранжирование из NPY обязано совпасть.
Экспортируемые векторы — источник двухэтапного scorer, а не обещание совпадения с простым cosine;
официальный mINP по cosine может отличаться от качества финального top-10.

TTA потребует дополнительных проходов всех четырёх encoder. Скорость/выигрыш нельзя обещать заранее;
измерение полного конкурсного performance — отдельный этап, данный notebook оценивает качество.
Ни один исход не меняет активный MVP v25 автоматически. Датасет NiVe остаётся локальным и не используется.
