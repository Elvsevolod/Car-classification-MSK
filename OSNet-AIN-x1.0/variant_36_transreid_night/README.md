# v36 — ночная серия TransReID / DeiT-Small

Открыть `train_transreid_night.ipynb`, выбрать прежнее окружение проекта `.venv` и
нажать **Run All**. По умолчанию `DEVICE='mps'`, `RUN_NAME='night_v1'`.
Новый пакет устанавливать не нужно. Официальные публичные веса уже скачаны в локальный
`weights/` и проверены; notebook скачивает их только при отсутствии. Токен не нужен.

## Что выполняется

| Параметр | Варианты |
|---|---|
| Архитектура | global DeiT-Small / TransReID JPM |
| Learning rate backbone | 1e-5 / 3e-5 / 1e-4 |
| Weight decay | 1e-4 / 1e-2 |
| Metric loss | batch-hard soft triplet / SupCon |
| Batch | 8 ID × 2 изображения = 16 |
| Короткое обучение | все 24 конфигурации до 400 шагов |
| Продолжение | четыре финалиста до 1800 шагов суммарно |

Это 15 200 обновлений optimizer, а не 24 полных обучения по 1800; 243 200 предъявлений
изображений, плюс четыре технических пробных шага. Проход по случайной P×K-выборке
не называется эпохой: в выводе честно показываются шаг, граница этапа, loss и время.
Опыты выполняются последовательно, без одновременного хранения нескольких обучаемых моделей.
Ограничения длительности нет; завершение за одну ночь не гарантируется.

Для каждой архитектуры сохраняются лучший одиночный encoder и лучший комплементарный
вариант в фиксированной смеси с R1. Если это один опыт, вторым идёт следующий по смеси;
при равенстве метрики решает порядок объявленной сетки. По две конфигурации каждой
архитектуры продолжают свой optimizer и то же cosine-расписание с горизонтом 1800,
100 шагами warmup, минимальным LR 2% и LR head ×10. Перезапуска LR при отборе нет.

Общие параметры: AdamW, label smoothing .1, metric weight 1, SupCon temperature .1,
gradient clip 5, drop-path .1; float32, без AMP/compile и скрытого CPU fallback.
Все опыты используют одинаковые train-ID, P×K-порядок и seed аугментаций по шагу.
Сравнение global/JPM при этом не является чистым исследованием одного архитектурного
фактора: различаются и размерность, и число supervised ветвей.

## С чем сравниваем

- Те же 740 train-ID и 185 внутренних holdout-ID, что у fold-matched R1 из v33.
- Те же три пересекающихся draw; объединение query/gallery — 1036 изображений.
- R1 reference: raw mAP@10 **0.8328422683**, less_graph **0.8440989714**.
- Сначала global/JPM без дообучения, затем checkpoints 400/800/1200/1800.
- Для каждого checkpoint: одиночный encoder и фиксированная смесь R1 90% / новый 10%;
  для обоих raw и less_graph (k1=20, k2=3, lambda=.75).
- Смесь — sqrt-weighted concatenation L2-векторов с итоговой нормализацией:
  896D для global и 2432D для JPM. Самостоятельные векторы — 384D / 1920D.
- Полные per-query AP, top-10 и Hit@50 сохраняются в `tasks/*/result.json`.

Это адаптивный выбор на одном многократно использованном inner holdout; три draw не
независимы. Ранний отсев на 400 шагах может потерять медленно сходящиеся варианты.
Сетка не исчерпывающая. Победа над этим R1 **не равна** победе над full-train v25
на другой выборке; системное сравнение остаётся следующим этапом.
Сохраняем конкретные лучшие веса, а не требуем лучшего среднего по seed.

## Ограничения данных и MVP

Исходные train bbox не меняются. Используется штатный EXIF-aware RGB bbox crop,
256×256 bilinear resize, ImageNet normalization; train augmentation: flip .5,
padding 10 / random crop, random erasing .25. Никакого OCR, детектора, номерной маски
или обработки номерной области. Вход модели — только изображение.
Identity нужен для train loss и оценки; camera_id — только существующему train sampler
и правилам оценки, не как вход модели. SIE_CAMERA и SIE_VIEW выключены.

NiVe не добавляется в train этой серии. Исходная calibration/validation не оценивается
и не правится; threshold не подбирается. Файлы старых запусков и активного приложения
проверяются по байтам, v25 не переключается. Проверка хешей внешних контрольных
артефактов не является использованием их метрик для отбора.

## Прогресс, восстановление и диск

- Вывод обучения каждые 25 шагов; resume каждые 50.
- `progress.json` и `REPORT.md` обновляются между опытами; финальные
  `results.json`, `finalists.json`, проверочный `complete.json` — в `runs/night_v1/`.
- `training/<trial>/step_*.pt` сохраняет все контрольные точки, а не только последнюю.
- Две служебные позиции optimizer используются атомарно: новая запись → pointer →
  удаление только прежней служебной копии **этой** серии. Обычно остаётся один resume
  на опыт. Исторические данные и selectable checkpoints никогда не удаляются.
- При обычном прерывании повторить Run All с тем же RUN_NAME. Завершённые этапы
  проверяются и переиспользуются с явной отметкой, не выдаются за новый замер.
- Если отдельный trial выдаёт NaN/нехватку памяти, он фиксируется в `failures`,
  очередь продолжается. Уже завершённые оценки не отбрасываются.
  Поздний сбой может оставить дополнительные неоценённые checkpoints на диске —
  их можно отдельно проанализировать после ночи. Неизвестные ошибки не скрываются.
- Не менять код, config, runtime или входные файлы на ходу. Изменение означает новую серию,
  а не перезапись manifest. Файл `.lock` остаётся штатно; операционная система освобождает
  его блокировку при завершении процесса. Удалять этот файл вручную не нужно.
- Для старта требуется примерно **13 GiB свободно**, включая запас. Проверка учитывает
  уже записанный объём текущего запуска. Автоматической очистки старых файлов нет.

Веса/эмбеддинги/resume исключены из Git локальным `.gitignore`; dataset не пушится.
Ничего не коммитится, не пушится и не переносится в main этим notebook.
Результаты здесь исследовательские; это не готовая конкурсная поставка с экспортом,
порогом и проверенным лимитом 2 ГБ.
