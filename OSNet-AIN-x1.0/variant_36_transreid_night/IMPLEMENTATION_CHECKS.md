# Проверки реализации v36 — 2026-09-27

## Статус

Ночной HPO **не запускался**. Подготовлены notebook Run All, фиксированная сетка,
сохранение/продолжение, локальная реализация global/JPM, отчёт и тесты.
Никакого подтверждённого прироста от дообучения пока нет.

Рабочий профиль приложения по-прежнему `MVP_fusion_v25`.
Новые записи ограничены v36, `training/transreid_*` и новым тестовым модулем.
Исходная разметка, веса, старые запуски и приложение не редактировались.
Commit/push/merge и запуск облачных заданий не выполнялись.


Проверены:

- 24 уникальные конфигурации, бюджет 15 200 обновлений, запреты outer/threshold/SIE.
- Настоящие официальные веса: strict loading 150 тензоров, отсутствие сети
  при локально подготовленных весах, ошибка при повреждении файла/недостающих ключах.
- Обе архитектуры: прямой проход, soft-triplet/SupCon backward, ненулевые градиенты
  backbone/heads/JPM; размерности 384/1920 и нормализация.
- JPM shuffle не включает CLS и сохраняет все 256 patch tokens.
- Loss weighting: .5 global + .5 mean-local; batch-hard triplet против ручного расчёта.
- JPEG/PNG, неоднозначные/отсутствующие ID, выход bbox за границы, метаданные не меняют tensor.
- Запрошенное недоступное устройство вызывает ошибку, не CPU fallback.
- CPU tiny-model: непрерывное обучение и остановка/продолжение дают точно одинаковые
  параметры, optimizer и историю loss; selectable weights не удаляются.
- Повреждённый resume отвергается; LR не перезапускается после 400 шагов.
- Полный контроллер на маленьких синтетических данных, повторное использование
  завершённого результата, обнаружение повреждённого cache.
- NaN отдельного trial не прекращает остальные; неизвестные RuntimeError не скрываются.
- Поздний отказ финалиста не теряет screen-результат и не меняет замороженный список.
- Успешный промежуточный checkpoint не теряется после сбоя оценки более позднего
  checkpoint и последующего перезапуска.
- Проверка свободного диска ничего не удаляет.
- Алгебра фиксированной смеси, независимость query, notebook format/compile.

## Реальная проверка на этом Mac

Изоляция инструментов не видела Metal; короткая проверка выполнена вне неё на
реально доступном **MPS**, без включения CPU fallback.

В `runs/implementation_mps_smoke_v1/` сохранены:

- manifest с 740 train-ID, 185 holdout-ID, 1036 evaluation images;
- проверенные 12 974 исторических/входных файла и 90 файлов исходного кода/конфигурации;
- четыре временных обновления (global/JPM × soft-triplet/SupCon) с настоящим batch 16;
- полное извлечение исходных признаков обеих моделей на 1036 изображениях;
- проверка лучшей исходной смеси при batch 1/8/16/32, обратном порядке и одиночном
  запросе против полной статической gallery.

Максимальное расхождение вектора: **2.9802322387695312e-08** при фиксированном допуске
2e-5. Raw и less_graph top-10 совпали точно. Model/BN state в evaluation не изменился.
Это ограниченная проверка исходного JPM; финальный выбранный checkpoint повторно
проходит её в ночном notebook. CPU bitwise-resume не является доказательством
битовой идентичности на любом GPU.

Метрики неизменённого R1 полностью воспроизведены, включая per-query решения:

- raw mAP@10: **0.8328422682886969**;
- less_graph mAP@10: **0.8440989714203999**.

Контроли **без дообучения** (не результат HPO):

| Модель | Самостоятельный graph mAP@10 | Фиксированная R1 90/10 смесь |
|---|---:|---:|
| global | 0.141705 | 0.836902 |
| JPM | 0.143145 | 0.837340 |

Эти контроли сами по себе R1 не улучшают; смысл следующего запуска — проверить
адаптацию представления к ReID обучением, а не объявить эти веса готовой заменой.

После последнего исправления восстановления оценок создан отдельный
`runs/implementation_final_preflight/`: финальная версия кода повторно проверяет
исходные файлы, точное воспроизведение R1 и четыре пробных обновления на MPS.
Первый smoke-manifest сохранён как историческое свидетельство версии до этого
исправления; его не переписывали под новый hash кода.
Оба каталога — только проверки реализации, **не** завершённая серия night_v1.

## Проверенная среда

Python 3.11.9, macOS arm64; torch 2.14.0, torchvision 0.29.0, numpy 2.4.6,
pillow 12.3.0, pandas 3.0.5, pytest 9.1.1, nbformat 5.11.1.
Новые зависимости не устанавливались. Runtime-версии и hashes записываются
в manifest каждого запуска. Веса локальные, проверка SHA256 обязательна.

## Что это не подтверждает

Качество дообученной модели, преимущество над v25, переносимость на скрытый тест,
остаточный сигнал номера, готовность конкурсного экспорта, порог отказа,
GPU NVIDIA/Linux и лимит веса конкурсной поставки не проверены этим этапом.
Нельзя считать совпадение inner-контроля независимой повторной validation.
Ночные результаты ещё должен получить пользователь запуском notebook.
