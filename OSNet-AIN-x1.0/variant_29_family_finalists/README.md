## Ровно три системы

| Система | Параметры | Calibration v28 |
|---|---|---:|
| V25_control | Исходный feature fusion 50/50, k1=20/k2=3/λ=0.50 | 0.8264099285 |
| power_50_l50 | Signed power γ=0.50 отдельно по MVP/R1; прежний fusion, λ=0.50 | 0.8333876952 |
| flip_mvp_w75_l50 | MVP: 25% original + 75% horizontal flip, L2; R1 прежний; fusion 50/50, λ=0.50 | 0.8287287069 |

Power и flip взяты как максимумы своих семейств в завершённом v28. Новый код проверяет этот
факт по полным защищённым calibration-результатам; другие победители/параметры не принимаются.
V28 остаётся историческим запуском с одним общим победителем — его plan/results не меняются.
V29 — **post-hoc development-сравнение**, отдельно разрешённое пользователем после просмотра v28.
Не независимая проверка, не доказательство качества скрытого теста. Лучший наблюдавшийся из
трёх показывается в отчёте, но не продвигается в MVP автоматически.

## Что выполняется

1. Тесты, проверка источников и фиксация `manifest.json`/`frozen_comparison.json`.
2. Точный replay трёх calibration-результатов с готовыми исходными и flip-признаками v28.
3. Validation-экспорты v25 и power.
4. Новое извлечение validation flip-признаков, сохранение каждых 128 изображений; затем flip-экспорт.
5. Общая таблица mAP/Rank-1/F1/TNR и парные изменения AP против v25.

Calibration flip не извлекается повторно. Validation flip использует тот же неизменённый
encoder/preprocessing/алгоритм v28 и перед первым новым блоком проверяет обычные признаки
на совпадение с исходным кэшем, с прежним допуском. Сохраняются реальные признаки всех
четырёх encoder для совместимости с v28 layout, хотя выбранный scorer меняет только MVP.

Кандидат, confidence и порог **всегда от исходного full R1 без TTA**. Файл candidates.csv
должен побайтно совпасть с v25. Контроль дополнительно воспроизводит прежний submission.csv
и embeddings.npy. При отказе submission всё равно содержит десять разных gallery ID.

Экспорт power/control: настоящие исходные float32 `(n_query+n_gallery,2048)`.
Экспорт flip: `(n_query+n_gallery,4096)` = original2048 + flipped2048. Порядок query→gallery.
Точная схема/параметры в `embedding_order.json`; NPY replay обязан воспроизводить top-10,
кандидатов и отказы. Это двухэтапный scorer, не обещание простого cosine-порядка.

Только текущий query и статическая gallery; между query информации нет. Допуск организаторов
для single-image TTA и re-ranking — вопросы 9–10, размерности/ансамблей — 8/16.
Нет query expansion, новых bbox, OCR, детекции, масок, внешних датасетов и изменения evaluator.

## Продолжение и результаты

Ошибки изолированных оценок сохраняются, независимые задачи продолжаются; неполный запуск
не получает статус complete и не называет общего победителя. Нарушение целостности прекращает запуск.
После прерывания используй то же RUN_NAME. Готовые задачи и flip-блоки проверяются и пропускаются.
Не редактируй код между частями; изменение кода требует нового RUN_NAME.
