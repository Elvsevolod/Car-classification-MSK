# v29: исправление SIGABRT после pytest — 2026-09-27

## Диагноз

Сохранённый notebook: `49 passed in 10.66s`, затем
`recursive_mutex lock failed: Invalid argument`, затем SIGABRT.
До `prepare` и validation-сравнения выполнение не дошло.
Исходный вывод notebook оставлен как свидетельство предыдущего запуска; после Run All он обновится.

В локальном отчёте macOS `Python-2026-09-27-125138.ips` основной поток завершает
`onnxruntime::PosixTelemetry::Shutdown()` → `LogManagerImpl::FlushAndTeardown()`.
Аварийный поток: `onnxruntime_pybind11_state.so` →
`Microsoft::Applications::Events::DebugEventSource::DispatchEvent()` → `recursive_mutex::lock()`.
Это сбой завершения телеметрии установленного ONNX Runtime 1.30.0, а не провал assertion.
Обычный повтор исходной команды здесь завершился нормально: ошибка воспроизводится не каждый раз.

## Изменение

- Первая ячейка задаёт `ORT_DISABLE_TELEMETRY=1` до импорта экспериментального кода и ONNX Runtime.
- Если библиотека уже загружена без настройки, ячейка требует перезапуска ядра.
- Подпроцесс pytest также получает эту настройку явно; `check=True` сохранён.
- Нет игнорирования SIGABRT, принудительного выхода, пропуска тестов или смены зависимостей.

Документированное отключение до инициализации не создаёт uploader телеметрии:
[ONNX Runtime Privacy](https://github.com/microsoft/onnxruntime/blob/v1.30.0/docs/Privacy.md).
Существующий вызов `disable_telemetry_events()` после импорта не эквивалентен этой настройке.
Проверено наличие `ORT_DISABLE_TELEMETRY` в установленной нативной библиотеке.
