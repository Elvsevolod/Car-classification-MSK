# Этап 3 — компактный обучаемый реранкер OSNet

Отдельный эксперимент по `RERANKING_IMPROVEMENT_PLAN.md`. OSNet заморожен, новый большой encoder не обучается. MVP, прежние weights, датасет, ручные маски и результаты сохраняются.

**Выполнено 22 сентября:** mAP@10 81,7764% против 81,4689% у MVP и 81,7191% у дешёвого контроля. Вклад новой головы мал; новый отказ ухудшил TNR. MVP сохранён. [Разбор результата](ANALYSIS.md). Для получения этих результатов повторный запуск не нужен.

## Запуск

Открыть `train_pair_reranker.ipynb`, выбрать существующее ядро `.venv`, нажать **Run All**. Из корня репозитория:

```bash
.venv/bin/python -m training.pair_reranker_experiment
```

Новые зависимости не устанавливаются. Весь эксперимент работает локально и без сети на CPU, 2 потока: для маленькой головы это не требует MPS. Прогресс включает время эпохи, оставшиеся эпохи и ETA; inference-кеш сохраняется каждый batch, обучение — каждую эпоху. Прерванный запуск продолжает работу. Завершённый проверяет контрольные суммы и читает отчёт. Один экземпляр одновременно; изменённым весам/коду/данным нужен новый `--output`, не удаление старых JSON.

## Честное разделение данных

1. Проверяем SHA кадров, splits, весов и кода. Используется существующее outer-разбиение: train 925, calibration 307, validation 309 identity; между частями не пересекаются identity и точные исходные кадры.
2. Для внутреннего отбора используем сохранённый **отдельный** OSNet `CLIP-ReID-ViT-B-16/variant_01_vehicle_transfer/weights/osnet_control/best_map.pt`. Он градиентно обучался только на 741 inner-train identity, не на остальных 184. Проверяем provenance, строгую загрузку state_dict, ONNX/PyTorch parity batch 1/2 и воспроизведение raw inner mAP@10 **0.7787153115**.
3. На 741 identity учим головы, на 184 выбираем архитектуру и эпоху. Это НЕ OOF: checkpoint контрольного OSNet ранее выбирали по этой inner validation. Она предназначена для отбора, не для независимой финальной оценки. Признаки текущего MVP здесь не используются — он уже видел все 925 identity.
4. Выбранный **рецепт** заново обучаем с нуля на признаках действующего MVP / всех 925 development-identity ровно выбранное число эпох. Веса головы между разными OSNet-пространствами не переносятся. Никакого early stopping по outer calibration/validation.
5. После фиксации головы calibration используется только для коэффициента смешивания и отказа; validation — только после сохранения `frozen_selection.json`. Уже использованная ранее validation не является независимым финальным тестом.

## Пары и признаки

`make_protocol(..., seed=20260915)` даёт один query на identity и статичную gallery; примерно 20% identity становятся open-set. В train/inner validation/development свой отдельный протокол. Для каждого query берётся **только исходный cosine top-50 OSNet**, без подмешивания правильных ответов вне пула или искусственно простых негативов.

Позитив — одинаковый vehicle_id, разные camera_id; негатив — другой vehicle_id. Same-identity/same-camera junk и точные дубликаты исходного кадра игнорируются в loss. На инференсе никакой фильтрации по GT/camera нет. BCE балансирует положительные/отрицательные пары внутри query, затем усредняется по query: каждое identity вносит равный вклад, 50 пар не считаются 50 независимыми объектами.

Голова получает 8 численных признаков: cosine, 1−raw distance, 1−Jaccard, k-reciprocal similarity, поддержку соседей gallery, mutual-neighbor indicator, позицию в raw top50 и отставание от максимального cosine. Полная версия дополнительно получает `sqrt(512)*|e_q−e_g|` и `512*(e_q*e_g)` — **1032 признака**.

Стандартизация mean/std обучается только на валидных train-парах и включается в ONNX. Ни vehicle_id, ни camera_id, ни имя файла, время, география или OCR не являются входными признаками. Галерейный граф статичен; другие query на текущее решение не влияют. Однако OSNet-признаки могут наследовать зависимость encoder от номеров/фона: голова не даёт гарантии её устранения.

## Заранее ограниченный поиск

- `scalar_linear`: линейный классификатор на 8 признаках, AdamW lr=.01, weight_decay=.001.
- `pair_mlp64`: 1032 → 64 → ReLU → dropout=.1 → 1, AdamW lr=.001, weight_decay=.001.
- Seed=20260915, query batch=32, максимум 25 эпох. Early stopping: после минимум 5 эпох, 6 эпох без улучшения.
- Отбор головы/эпохи: официальный inner top-50-head mAP@10, затем Rank-1, ранняя эпоха, порядок сетки. В этот момент outer-метрики недоступны функции обучения.
- На calibration смешиваем фиксированный дешёвый neighborhood-контроль первого этапа с sigmoid-оценкой головы: `score=(1−beta)*(1+baseline_score)+beta*pair_score`, beta=`0,.1,.25,.5,1`. При равных mAP/Rank-1 предпочтение меньшей beta. Raw top-50 остаётся неизменным; одинаковые score разрешаются порядком gallery CSV.
- Для отказа: `max_cosine`, `max_pair`, `selected_pair`. Порог выбирается по официальному `.7*F1+.3*TNR`, затем F1. Sigmoid — оценка пары, не калиброванная вероятность.
- После фиксации сравниваем: MVP; старый neighborhood-контроль; выбранное ранжирование со старым отказом; выбранное ранжирование с новым отказом; диагностическую выдачу только по голове.

## Артефакты и проверки

В `results/run_01/` сохраняются:

- `experiment.json`: хеши, полные train/inner/outer identity, query/gallery, recipe;
- `cache/inner.npz`, `cache/development.npz`: отдельные 512-D эмбеддинги разных OSNet;
- `weights/control/`: inference-экспорт OSNet только для inner-подготовки, не для итогового deployment;
- `weights/inner/<head>/`: last/selected checkpoints и история каждой головы;
- `inner_selection.json`: выбор архитектуры и эпохи до outer;
- `weights/final/`: новая head на MVP-признаках, экспорт ONNX с batch1/50/100 parity;
- `calibration.json`, `frozen_selection.json`: ограниченный выбор смешивания и отказа;
- `RESULTS.md`, `report.json`: метрики, per-query, парный bootstrap, размеры и замеры;
- `validation/`: локальные CSV пяти систем и **неизменённые OSNet embeddings.npy**. Не организаторский test и не база MVP.

Все CSV повторно читаются неизменённым evaluator организаторов. `submission.csv` всегда содержит десять ID, отказ — отсутствие строки в `candidates.csv`. mAP@10/Rank-1/5 оценивают финальный порядок, full_mAP/mINP — исходные эмбеддинги.

Исправленный ручной аудит `masks-7` на 126 кропах проверяется с той же головой и порогом, без обучения или выбора параметров. Он не доказывает полную независимость от номеров.

Замеряется весь локальный поиск после OSNet: top50, парные признаки, head, смешивание и отказ. `extract()` остаётся прежним OSNet. Лимит 2 GB проверяется для MVP ONNX + итоговой head ONNX; тренировочный контроль в deployment не включается. Скорость/VRAM RTX A5000 здесь не проверяются. Продвижения в MVP автоматически нет.
