# Парное сравнение двух моделей на трёх вариантах изображения

Изолированный диагностический эксперимент. **Ничего не обучает, не подбирает и не меняет в MVP.**

## Что сравниваем

- Активный MVP: OSNet-AIN x1.0, HPO best-mAP epoch 5.
- Masked-trained: `variant_08_masked_hpo`, selected best-mAP epoch 16, экспорт ONNX.
- Для каждой модели: исходный кроп, ручная непрозрачная маска, автоматическая непрозрачная маска YOLO11.

Все шесть комбинаций используют один зафиксированный протокол из старого ручного аудита:
32 query, 94 gallery, всего 126 кропов. Ручные маски — исправленная версия `masks-7.json`,
сохранённая в `Mask-Detectors/reference_v02/results/masks.json` (157 областей).
Маскирование обеих сторон поиска происходит после BBox-кропа и перед resize 208×208.

Автоматические маски берутся из hash-locked кэша **того же masked HPO**, а не генерируются заново:
confidence=0.20, margin=0.10 с каждой стороны. Проверяются контрольные суммы кэша, весов,
калибровки, связи с обучением и экспортом; ручные координаты, BBox и исходные 126 кадров.
Подвыборка должна относиться к outer validation и не пересекаться с данными детектора
по image_id, vehicle_id или точному полному кадру.

Порог у каждой модели собственный, взятый из её ранее сохранённой калибровки:
MVP ≈0.5948754549, masked-trained ≈0.5620952845. **Он одинаков во всех трёх условиях**,
а не подбирается заново. Реранкинг одинаков: k1=20, k2=3, lambda=0.5. Без TTA.

## Запуск

Из корня `Car-classification-MSK`:

```bash
.venv/bin/python -m training.mask_model_comparison
```

Или открыть `compare_models_masks.ipynb`, выбрать kernel проекта и выполнить Run All.
Установка зависимостей, загрузка моделей и обучение не выполняются.
Повторный запуск проверяет входы и переиспользует завершённый результат без повторного инференса.
При изменении входов/кода нужно выбрать новую папку, например `--output OSNet-AIN-x1.0/audit_09_model_mask_comparison/results/comparison_v2`.
Не удаляйте прежние результаты для обхода проверки.

## Выходы в results/comparison_v1

- `RESULTS.md` — таблица шести комбинаций и ограничения интерпретации.
- `comparison.json` — официальные метрики raw/reranked, top-10/confidence по query,
  парные изменения, bootstrap-интервалы и согласие масок по каждому кропу.
- `embeddings.npz` — шесть наборов нормированных 512-D эмбеддингов; `ids` задаёт общий порядок query → gallery.
- `experiment.json` — протокол, фиксированные пороги, контрольные суммы и версии runtime.

## Как понимать результат

Сначала сравнивайте original → manual внутри каждой модели, затем manual → yolo.
Это проверка чувствительности готовых моделей к замене пикселей и к различиям масок,
**не доказательство полной независимости от номера и не чистый причинный тест обучения с масками**.
HPO и checkpoint selection у моделей различались; ручная разметка включает разные области анонимизации.
Пропуски YOLO и лишняя закрытая площадь меняются одновременно.
Шесть unknown-query — слишком мало для уверенного обобщения TNR.
Высокий результат на маленькой gallery нельзя сравнивать напрямую с полной validation или закрытым тестом.
На этой выборке запрещено подбирать пороги/маски или автоматически выбирать модель для MVP.
