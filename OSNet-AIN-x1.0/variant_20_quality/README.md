# Variant 20: следующая серия именно на качество

Открыть `run_quality_experiments.ipynb` в прежнем research `.venv`, затем
**Restart Kernel → Run All**. Ничего не нужно запускать на другом устройстве.
Notebook не обучен заранее; полное обучение выполняет пользователь.

## Последовательность

1. Синтетические тесты и read-only проверка завершённых v16/v18.
2. Диагностика primary: ошибки retrieval/top-50 и ошибки порядка, graph vs raw,
   HTML с реальными исходными crop. Это диагностика, не оценка новых весов.
3. Компактная обучаемая pair-head на локальных 4×4 признаках frozen R1.
   Основной контролируемый результат — ranking mAP@10.
4. Три обучающих пилота OSNet, пять оценок:

| Вариант | Обновления / LR horizon | Что проверяет |
|---|---|---|
| R1_control | 800 / 1700 | Сопоставимый контроль из stock |
| R1_cosine800 | 800 / 800 | Завершить cosine при прежнем числе обновлений |
| R1_full1700 | 1700 / 1700 | Полный график, больше обновлений |
| R1_full1700_bn | те же веса 1700 | Только пересчёт BatchNorm на train |
| R1_full1700_avg | среднее 1400/1600/1700 | Усреднение + такой же пересчёт BN |

Это checkpoint averaging, не EMA по каждому update. Увеличение длительности
не объявляется исправлением ошибки: это новая проверяемая гипотеза.
R1_cosine800 имеет тот же warmup=100, sampler, loss, augmentations и batch;
R1_full1700 до шага 800 следует тому же режиму, что контроль.
Другие поколения K2, KD, GeM/MixStyle, новые backbones и датасеты не добавлены.

## Парная модель

У каждого из трёх заранее фиксированных R1 seed своя голова. Encoder заморожен.
Train головы: до четырёх camera-diverse изображений на identity из train
соответствующего fold. Это не удаление/редактирование строк dataset.
Cross-camera пары одного ID — положительные; похожие другие автомобили из
реального cosine top-50 — отрицательные. Same-ID/same-camera junk исключается
из обучения пар, но не удаляется из конкурсного ranking.

Вход головы — симметричная 16×16 матрица локальных соответствий, сводки лучших
локальных совпадений и raw cosine. Ни camera_id, ни vehicle_id, ни имя файла
не подаются модели. MLP 289→64→1, 12 фиксированных эпох, train-only normalizer,
AdamW; sigmoid — добавка к score, **не калиброванная вероятность**.
Top-50 pool и хвост ranking сохраняются; веса добавки заранее 0.05/0.10.
`raw_top1` и raw-confidence остаются прежними: кандидаты/отказы головы неизменны
при любом фиксированном пороге.

Обе обучаемые части проверяются на held-out identity. Голова учится на
encoder-train признаках: это не OOF, результаты train не выдаются за качество.
На evaluation ни encoder, ни head не видели identity. Frozen local scorer v19
не учился различать пары; это отдельная гипотеза, а не повтор его коэффициентов.
Пилот по каждому seed — отдельный R1, **не** оценка ансамбля equal3 с новой головой.
Положительный результат не запускает автоматическое объединение систем.

## Отбор без утечки

- Head: средний прирост primary ≥0.002 mAP (0.2 п.п.) и плюс минимум на 2/3 seed.
  Один выбор замораживается; alternate проверяет его, не перебирает веса заново.
- Clock: pilot первого seed ≥0.003 относительно R1; averaging должен также
  обойти BN-only на ≥0.003. Затем три seed primary и alternate с gate ≥0.002
  и улучшением минимум на 2/3 seed относительно каждого обязательного контроля.
- Самый удачный seed/epoch не выбирается. При равенстве сохраняется baseline.
- Bootstrap группируется по identity; повторные draw/seed не объявляются
  новыми независимыми автомобилями. Интервал условный, не гарантия на закрытом тесте.
- C/F1/TNR clock — отдельная диагностика: threshold выбирается на одной
  identity-половине inner, оценивается на другой. По ней нет отбора рецепта.
  Для рабочего релиза это не готовая калибровка.
- Outer validation, test и full-train обучение не вызываются. Исторический MVP
  был выбран с использованием outer; сравнение inner с его 0.8147 некорректно.

Primary/alternate уже использовались в предыдущих исследованиях. Это
контроль утечки между обучением и оценкой, но не новый независимый слепой тест.

## Продолжение и безопасность

По умолчанию `RUN_HEAD=True`, `RUN_CLOCK=True`, `AUTO_CONFIRM=True`.
Нет общего тайм-аута. Сохраняются stage status, loss/ETA, head после каждой
эпохи, encoder на прежних границах блоков. Один RUN_NAME возобновляет тот же
неизменённый рецепт. Для другого кода/настроек нужен новый RUN_NAME.
Нет автоснижения допусков, отключения integrity-check и замены baseline при ошибке.

Manifest фиксирует источники, разбиения, настройки, версии, SHA256 весов/кода.
Checkpoint/cache corruption блокирует использование. Финальная проверка
повторно сверяет исходные фотографии, разметку, MVP, старые результаты.
Все новые файлы — только `variant_20_quality/runs/<RUN_NAME>`.
`release-integration` не меняется; NiVe остаётся локальным и не используется.

Отчёт: REPORT.md + results.json; визуальные примеры:
tasks/diagnostics_primary/errors_*.html. Если pilot отрицательный, отчёт
зафиксирует baseline; дорогая confirmation этой гипотезы не запускается.
При ошибках независимые задачи продолжаются, целостность/KeyboardInterrupt
останавливают очередь. Прерванный блок может переиграться, завершённые защищены.

BatchNorm при усреднении пересчитывается только по train без аугментаций:
в train-mode переводятся только BN, dropout остаётся выключенным, singleton
batch объединяется с предыдущим. Основание —
[PyTorch 2.14: averaging and BatchNorm](https://github.com/pytorch/pytorch/blob/v2.14.0/docs/source/optim.md).
Номерная зона не обрабатывается; отсутствие остаточного сигнала не доказано.
GPU-баллы, новый outer-результат и улучшение качества заранее не обещаются.
