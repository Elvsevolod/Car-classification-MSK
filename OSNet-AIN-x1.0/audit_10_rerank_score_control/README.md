# Этап 1: контроль реранкинга и отказа

Изолированный эксперимент на готовых эмбеддингах **активного OSNet HPO epoch 5**.
Не обучает encoder или дополнительную голову, не подключает CLIP, не изменяет MVP.
Исходные кропы без TTA и без автоматического маскирования. Все параметры выбираются
только на calibration; выбранный вариант записывается на диск **до** оценки validation.

## Запуск

Открыть `rerank_score_control.ipynb` с kernel репозиторного `.venv` и выполнить **Run All**.
Либо из корня `Car-classification-MSK`:

```bash
.venv/bin/python -m training.rerank_score_control
```

Зависимости не устанавливаются, веса не скачиваются. Используется ONNX CPU только
для контрольного пересчёта 16 кропов; основной поиск работает с готовым кэшем OSNet.
Проверяются hashes исходных кадров, сплитов, весов, кода и файлов MVP.
Нужен сохранённый `artifacts/stage2_embeddings_01466f503232.npz` и результаты
`audit_09_model_mask_comparison/results/comparison_v1` для ручного масочного контроля.

Повторный запуск проверяет контрольные суммы и переиспользует полный результат.
После прерывания до заморозки выбор пересчитывается на calibration; после заморозки
используется сохранённый выбор. Не запускать два экземпляра в одну папку одновременно.
При изменении кода/входов выбирается новая папка через `--output`, без удаления истории.

## Заранее зафиксированная сетка

13 вариантов ранжирования:

1. Текущий полный k-reciprocal: k1=20, k2=3, lambda=0.5 — неизменный контроль.
2. Полный raw cosine — контроль.
3. Те же k1/k2/lambda, но только исходный top-50 по cosine.
4. Для top-50 по одному изменению: k1=10/30; k2=1/6; lambda=0.35/0.65.
5. Top-50 с добавкой поддержки соседями весом 0.1/0.2.
6. Top-50 с добавкой взаимного соседства весом 0.025/0.05.

Новый score: `-((1-lambda)*jaccard + lambda*raw_distance)` плюс
`support_weight*(mean_neighbor_cosine-1)/2 + mutual_weight*mutual`.
Поддержка — средний cosine текущего query с тремя ближайшими к кандидату объектами
**статичной gallery**, без самого кандидата. Mutual=1, если кандидат в top-k1 query
и расстояние query до кандидата не превышает его сохранённую gallery k1-границу.
Метки identity/camera не доступны этим функциям. Граф не меняется между query.
Все новые варианты получают один исходный top-50; фильтрация junk остаётся у evaluator.

Порядок выбирается по максимальному **calibration mAP@10**, затем Rank-1;
при полной ничьей предпочтение более раннему варианту сетки (первый — действующий MVP).

## Отказ — отдельный эксперимент

Для действующего и выбранного порядка независимо сравниваются шесть функций:

- Максимальный исходный cosine (действующий способ).
- Cosine именно кандидата, выбранного после реранкинга.
- Финальный score выбранного кандидата.
- Cosine выбранного + 0.1 × разрыв между первым и вторым исходными cosine.
- 0.9 × cosine выбранного + 0.1 × поддержка его gallery-соседями.
- Cosine выбранного + 0.05 × индикатор взаимного соседства.

Порог каждой функции выбирается по **0.7F1+0.3TNR на calibration**, затем F1,
затем большему порогу. При ничьей функций сохраняется более простая первая.
Быстрый перебор порогов проверен на совпадение с неизменёнными функциями организатора;
в итоговые отчёты метрики идут непосредственно из них.
Разрыв top-1/top-2 — гипотеза, не правило: оба изображения могут быть одной машиной.
Уверенность не считается вероятностью. Коэффициенты этой сетки не обучаются градиентно.

## Итоговая проверка

На validation одновременно проверяются четыре заранее определённых варианта:

- `baseline`: действующие порядок и отказ.
- `ranking_only`: выбранный порядок, **прежние** max-cosine и порог.
- `refusal_only`: прежний порядок, выбранные на calibration уверенность и порог.
- `combined`: выбранные порядок и отказ.

Это абляция источника эффекта, а не выбор победителя по validation.
Исходные calibration/validation метрики MVP обязаны воспроизвестись.
Замороженные правила также применяются к 126 original/manual-v2 кропам прошлого аудита:
никакой настройки по ручным маскам не проводится.

## Артефакты в results/run_01

- `experiment.json` — контрольные суммы, сетка и условия.
- `calibration.json` — все 13 вариантов и кривые порогов 6 функций.
- `frozen_selection.json` — выбор до открытия validation-метрик.
- `report.json`, `RESULTS.md` — итоговые метрики, timing, масочный аудит,
  AP/top10/confidence каждого query и парный bootstrap.
- `validation/` — общий `embeddings.npy`, локальные query/gallery/ground-truth CSV;
  для четырёх вариантов отдельные `submission.csv` и `candidates.csv`.
  Эти файлы предназначены **только для локальной validation**, не для отправки организаторам.
  CSV перечитываются эталонными парсерами и проверяются на совпадение метрик.

Ранжирование не зависит от отказа: submission всегда содержит десять ID,
даже если query отсутствует в candidates. Исходные эмбеддинги не меняются.
CPU timing включает поиск/score/top10/confidence после извлечения эмбеддинга,
но не является замером extract на RTX A5000. Дополнительных файлов весов нет.

## Правило интерпретации

Ориентир для ранжирования — около +1 п.п. mAP@10 без существенного падения F1/TNR.
Улучшение отказа при неизменном mAP оценивается отдельно по F1, TNR и их взвешенной метрике.
Не менять сетку по результатам validation и не внедрять результат в MVP автоматически.
Validation уже использовалась в предыдущих экспериментах; bootstrap и ручной аудит
не превращают её в независимый закрытый тест и не доказывают независимость от номеров.
