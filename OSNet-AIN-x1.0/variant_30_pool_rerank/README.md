# v30 — реранкинг внутри исходного пула

Запуск: `search_pool_rerank.ipynb`, прежний research `.venv`, **Restart Kernel → Run All**.
Нужны завершённый `variant_29_family_finalists/runs/family_finalists_v1` и его неизменные локальные источники.
Ничего скачивать, обучать или переносить на другое устройство не нужно.

Четыре фиксированных сравнения:

| Вариант | Пул | Порядок |
|---|---|---|
| V25_control | Вся gallery | Точный текущий v25 |
| raw_pool10 | Raw fusion top-10 | Порядок v25 внутри пула |
| raw_pool20 | Raw fusion top-20 | Порядок v25 внутри пула |
| raw_pool50 | Raw fusion top-50 | Порядок v25 внутри пула |

Raw fusion — исходный cosine MVP/R1 50:50. Граф v25 строится на полной статической gallery:
k1=20, k2=3, λ=0.50. K пула не меняет k1. Кандидаты вне пула не могут попасть внутрь;
хвост остаётся в raw-порядке. Отдельный кандидат для принятия/отказа — прежний raw R1,
не обязательно первый результат нового ranking. Confidence и замороженный порог неизменны.

## Протокол

Все четыре результата считаются на calibration. После полного успешного сравнения
выбирается максимальный mAP@10; при точном равенстве приоритет у v25.
Выбор фиксируется до загрузки validation-векторов. На validation считаются контроль и
только один выбранный вариант (или один контроль, если он победил).
Это продолжение адаптивного поиска на уже наблюдавшихся development-данных,
не независимое подтверждение качества на скрытом тесте. Прирост не гарантирован.

Нет новых весов, обучения, извлечения признаков, подбора порога, изменения bbox,
исходной validation, evaluator или рабочего MVP. Нет OCR, обработки номерной зоны,
query-query обмена или использования camera_id/vehicle_id как входных признаков.
Метки используются только неизменным evaluator для измерения результата.

## Результаты и возобновление

Новый каталог: `runs/pool_rerank_v1`. В нём `manifest.json`, `frozen_selection.json`,
`results.json`, `REPORT.md`, прогресс и отдельные task-каталоги.
Готовые задачи проверяются по контрольным суммам и переиспользуются.
После прерывания запустить тот же notebook с тем же RUN_NAME. Не удалять receipts
и не менять конфигурацию ради продолжения: при изменении источников запуск остановится.
Лимита времени нет; показываются этап, номер варианта, метрики и время текущего вызова.

Для validation сохраняются три файла: десять разных gallery-ID на каждый query в
submission.csv, принятые raw R1-кандидаты в candidates.csv и реальные float32-векторы
2048 измерений (query, затем gallery) в embeddings.npy. Отказы не удаляют ranking.
Кандидаты и embeddings должны побайтно совпасть с v25; для контроля совпадает и ranking.
Ограничение junk/top-10 не исправляется: из десяти ID evaluator не восстановит 11-е место.

Телеметрия ONNX Runtime отключается до его загрузки, включая процесс тестов:
сохраняется защита от ранее диагностированного macOS SIGABRT. Ошибки тестов не скрываются.
Это изолированный эксперимент; переноса в приложение или автоматического продвижения нет.
