# Этап 2: общий протокол OSNet + CLIP

Отдельный inference-эксперимент. Не меняет MVP, старые веса, изображения, разметку или результаты. Дополнительное обучение, внешние данные и установка зависимостей не нужны.

**Выполнено 22 сентября:** validation mAP@10 ансамбля 81,3549% против 81,4689% у MVP; F1 выше, TNR ниже. MVP сохранён. [Разбор результата](ANALYSIS.md), [машинный отчёт](results/run_01/RESULTS.md). Повторный запуск для получения этих метрик не нужен.

## Запуск

Открыть `osnet_clip_ensemble.ipynb`, выбрать ядро существующего `.venv`, нажать **Run All**. Альтернатива из корня репозитория:

```bash
.venv/bin/python -m training.ensemble_experiment
```

Один запуск одновременно. Прерванный запуск продолжит CLIP inference с последнего сохранённого batch; завершённый только проверит контрольные суммы и вернёт отчёт. Не удалять JSON для перезапуска: изменённые веса/код/настройки требуют нового `--output`. Проверка всех исходных кадров выполняется и при повторном запуске.

Будет создан один image-only CLIP ONNX (~330 MiB), небольшой кеш эмбеддингов и отчёты. CLIP экспортируется на CPU; обучение не запускается. Прогресс inference показывает количество кропов и ETA. Существующие OSNet-векторы проверяются по порядку, размерам, нормам, provenance и 16 свежим предсказаниям. Изображения не копируются.

## Что зафиксировано до результатов

- OSNet: текущий MVP, 512-D; CLIP: `variant_02_hpo/weights/trial_011/image_best.pt`, epoch 33, before-BN concatenation 1280-D. Image-only ONNX проверяется против PyTorch на batch 1/2.
- У CLIP было 741 inner-train identity, у OSNet 925. Здесь одинаковые условия **оценки**, но не объём обучения. Повторное обучение CLIP на 925 в этот этап не входит.
- Оригинальные BBox/EXIF/RGB; OSNet square208/ImageNet normalize; CLIP square256/mean=.5/std=.5. Каждому — свой исходный preprocessing; без TTA и масок в основном сравнении.
- Общие outer calibration 307 query / 895 gallery и validation 309 / 896. Проверяются непересечение train/calibration/validation по identity и хешам кадров, CLIP inner-split, provenance checkpoint, evaluator.
- Слияние: `L2(concat(sqrt(alpha)*L2(osnet), sqrt(1-alpha)*L2(clip)))`; cosine равен взвешенной сумме двух cosine. Не складываем координаты разных пространств. Alpha — доля OSNet: `1, .9, .75, .5, .25, 0`.
- 12 full-gallery контролей (6 alpha × raw/фиксированный k-reciprocal 20/3/.5), ещё 4 контроля смешанных alpha с дедуплицированным union двух raw top-50. Граф строится по статичной полной gallery, ограничение union применяется к выдаче. Query никогда не влияют друг на друга.
- Из reranked вариантов выбирается лучший на calibration: mAP@10, Rank-1, большая alpha, full pool, порядок сетки. Raw cosine остаётся отдельным контролем. Для выбранной alpha/pool проверяется только шесть дополнительных изменений одного параметра: k1=10/30, k2=1/6, lambda=.35/.65. Никакого расширения поиска после validation.
- Для каждого варианта порог подбирается на calibration по официальному `.7*F1+.3*TNR`, затем F1, затем большему порогу. Confidence — максимум fused cosine, не вероятность. Выбранные thresholds и конфигурации сохраняются до validation inference/метрик.
- Validation сравнивает MVP, фиксированный neighborhood-контроль этапа 1, CLIP raw/reranked, fusion fixed/refined. Не выбирает победителя и не меняет пороги.
- Дополняемость: raw top1 ошибки двух моделей; наличие валидного позитива и доля найденных позитивов в top10/top50/union; недостижимая oracle-граница mAP@10. Только диагностика, GT не используется при поиске.
- Отдельный повторный аудит исправленных `masks-7`: 32 query + 94 gallery, opaque masks до resize у обеих моделей; те же пороги до/после. Это не доказательство полной независимости от номеров.
- Локальные CPU extract-замеры включают чтение/кроп/два transform/энкодеры/fusion. Поиск измеряется отдельно, включая два cosine lookup и union, если он выбран. Конкурсный RTX A5000 и VRAM здесь не проверяются. Совокупный размер двух inference ONNX ограничен 2 GB.

## Результаты

`results/run_01/`:

- `experiment.json` — неизменяемые входы, код, веса, splits, preprocessing и сетка;
- `weights/clip_trial_011.onnx`, `weights/export.json` — экспорт и parity;
- `cache/*.npz` — продолжение inference без повторного расчёта готовых batch;
- `calibration.json` — все испытания, пороги/кривые отказа и дополняемость;
- `frozen_selection.json` — выбор **до** validation;
- `report.json`, `RESULTS.md` — сравнение, парный bootstrap, масочный аудит и скорость;
- `validation/<system>/` — локальные query/gallery, GT, embeddings; `predictions/submission.csv` всегда содержит 10 ID, отказ — отсутствие строки в `candidates.csv`. Файлы проходят повторное чтение неизменённым evaluator организаторов. Это не официальный test и не база MVP.

`full_mAP/mINP` по контракту evaluator относятся к cosine-эмбеддингам; `mAP@10/Rank-1/5` — к отправленному ранжированию. Validation использовалась в прошлых экспериментах: считать её независимым итоговым тестом нельзя. Автоматического внедрения победителя нет.
