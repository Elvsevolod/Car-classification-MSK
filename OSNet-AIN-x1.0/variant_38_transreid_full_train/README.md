# v38 — полный train для одного выбранного T12

Открыть `train_transreid_full_train.ipynb`, выбрать `.venv` проекта и **Run All**.
По умолчанию `DEVICE='mps'`, `RUN_NAME='refit_v1'`. Ограничения времени нет.
Нужны локальные результаты v36/v37, артефакты v24/v25 и уже скачанные официальные DeiT-веса.
Ничего дополнительно скачивать, менять в `main` или подключать NiVe не нужно.

## Что проверяем

В v37 сохранённый T12 на 740 train-ID улучшил calibration, но смесь 90/10 проиграла v25 на validation:
`0.821831` против `0.828957`. Это не является новым лучшим результатом.

Теперь **один полный refit выбранного рецепта на всех 925 разрешённых train-ID**.
Инициализация заново из тех же официальных pretrained-весов DeiT. Старый обученный T12 не является initializer.
Старая 740-классовая голова не переносится: создаётся новая голова на 925 классов.
Сохранённые T12/T22 и все прошлые результаты не изменяются.

Фиксированы до обучения:

- Global 384D, CE + SupCon, lr `1e-4`, weight decay `.01`, seed `20260915`.
- **1800 optimizer steps**, batch **8 идентификаторов × 2 кадра = 16**.
- Одна оцениваемая точка: final `step_01800.pt`, без выбора по loss/calibration/validation.
- Смесь **90% v25 + 10% Full T12**, legacy graph **20/3/.50**.
- Прежняя кандидатская ветвь R1 equal3, её confidence и threshold `0.534365177154541`.

Число шагов оставлено тем же, а не масштабировано до 2250: это сохраняет тренировочный бюджет/расписание.
Среднее число показов каждого ID при 925 ID будет ниже, чем при 740 — это отмечается в отчёте.
Прежние 185 inner-holdout ID входят в полный train и больше **не оцениваются как holdout**.
Original calibration/validation полностью исключены из обучения и не исправляются.

## Порядок Run All

1. Тесты, контрольные суммы, проверка train/outer разделения и фиксация manifest.
2. Один одноразовый smoke-update на выбранном устройстве, затем модель отбрасывается.
3. Единственное рабочее обучение: 1800 шагов от pretrained, без оценки внешних выборок по ходу обучения.
4. Фиксация final checkpoint и смеси до извлечения признаков calibration/validation.
5. Проверка batch 1/8/16/32, перестановки/удаления query, точных top-10 и неизменности inference-буферов.
6. Две системы на обоих разбиениях: v25 и фиксированная смесь с Full T12. Raw mAP — только диагностика той же смеси.
7. Экспорт, побайтная проверка candidate CSV, NPY replay и итоговый отчёт; старый T12/740 показан как историческая справка.

Нет подбора весов, графа, seed, checkpoint или порога. Обе внешние выборки уже наблюдались ранее:
это development-сравнение, не новая независимая оценка и не причинное доказательство влияния одних только 185 ID.
Если новая смесь проигрывает, она не становится MVP автоматически. При выигрыше перенос в продукт также отдельный шаг.

## Прогресс и продолжение

Логи — каждые **25** шагов, сохранение optimizer/RNG — каждые **50**.
Это обычные батчи по 16 изображений; 50 — интервал сохранения, не размер батча.
Повторный Run All с тем же `RUN_NAME` продолжит с сохранённого состояния.
При прерывании между сохранениями повторится несохранённый остаток, завершённые оценки переиспользуются с проверкой хешей.
Параметры/код/устройство нельзя менять под тем же именем. Повреждённый checkpoint не перезаписывается молча.
Завершённый запуск проверяется без повторного обучения. Старые экспериментальные файлы не удаляются.
Для атомарного сохранения новых optimizer-слотов требуется минимум **2 GiB** свободного места.

Результаты: `runs/refit_v1/REPORT.md`, `results.json`, `frozen_candidate.json`.
История loss: `training/T12_global_supcon/history.json`.
Три файла: `tasks/<split>_<system>/export/{submission.csv,candidates.csv,embeddings.npy}`.
Контроль имеет 2048D, новая система 2432D; это реальные unit-блоки с явными slices, не единый cosine-вектор.
`model_provenance.json` связывает экспорт с полным checkpoint, несмотря на переиспользование геометрии смеси из v37.
В JSON `raw_ranking` — диагностика полной смеси до графа; `per_query.raw` — прежняя кандидатская ветвь R1, а не эта смесь.

Это локальный PyTorch/MPS quality runner с CPU ONNX-кэшем v25, не новая поставочная ONNX-сборка.
Скорость/GPU/Linux, номерная устойчивость и открытый вопрос junk/top-10 не объявляются решёнными.
`MVP_fusion_v25` и `main` не меняются. Все новые файлы относятся к `fine-tuning`.
