## Архивные инструкции запуска

Открыть `evaluate_dino_frozen.ipynb`, выбрать kernel существующего `.venv`, **Run All**. До первого полного запуска требуется одобрение доступа к [официальной модели](https://huggingface.co/facebook/dinov3-vits16-pretrain-lvd1689m) и локальный вход пользователя. Инструкции входа — в первой ячейке notebook. Токен не вставляется в notebook, конфиг или чат.

Дополнительные пакеты из `requirements-d0.txt` устанавливаются в локальный `.deps/` этого варианта через pip/uv с `--no-deps`. Корневые зависимости и существующие Torch/NumPy не обновляются. Проверенное окружение: Python 3.11.9, torch 2.14.0, torchvision 0.29.0, numpy 2.4.6; точные версии записываются в manifest каждого запуска. Перенос на другую машину отдельно не проверен.

По умолчанию CPU, batch 16, блок сохранения 128 изображений, без лимита времени. `DEVICE` можно явно изменить на `mps`/`cuda`, если устройство доступно. Скрытого fallback нет; новое устройство/окружение требует нового `RUN_NAME`. Неполный запуск с теми же входами возобновляется по проверенным блокам. Готовые этапы отмечаются как кэш, а не новые измерения.

Сеть нужна только для установки/скачивания. Encoder использует `local_files_only=True`, safetensors и точную проверку всех ключей checkpoint. Если все файлы уже на месте и их хеши верны, скачивания нет. Ни доступ, ни лицензия не принимаются автоматически; зеркал и замены backbone нет.

## Зафиксированный опыт

| Система | Признаки | Размер |
|---|---|---:|
| R1_control | прежний fold-matched R1, кэш N_ref v33 | 512 |
| D0_frozen | L2(CLS) + L2(mean patches), concat / √2 | 768 |
| R1_90_D0_10 | concat(√0.9 × R1, √0.1 × D0), L2 | 1280 |

Ровно одна модель, один pooling, одна смесь, без сетки коэффициентов.

- Источник сравнения — завершённый v34 `system_v1`; через его зафиксированную provenance используется inner из v33 `low_aux_v1`.
- R1 обучался на 740 train-ID, holdout содержит 185 других ID; все находятся внутри исходного train. Объединение трёх прежних draw — 1036 фотографий. Эти draw перекрываются, не являются тремя независимыми тестами.
- На том же порядке изображений R1 должен **точно** повторить исходные per-query top-10 и метрики N_ref: mean raw 0.8328422682886969, mean less_graph 0.8440989714203999.
- Active full-train v25 не используется как inner-контроль: он видел эти ID. Метрика 0.828957 на original validation относится к другому протоколу, прямое численное сравнение некорректно.
- Raw и фиксированный less_graph (k1=20, k2=3, λ=0.75) считаются для всех трёх систем. Query обрабатывается только относительно статической gallery.
- Сохраняются mAP@10, Rank-1/5, Hit@10/50, per-query AP/top10, улучшенные/ухудшенные запросы и пересечение ошибок. Для mAP используется существующий официальный evaluator без изменений.
- Backbone всегда `eval()`, все веса `requires_grad=False`, инференс в `inference_mode`. После извлечения параметры и буферы должны побитово совпасть с исходными.
- Реальные изображения дополнительно проверяются с batch 1/8/16/32, перестановкой и удалением соседних query. Допуск вектора 2e-5; raw/graph top-10 должны совпадать точно. При нарушении — остановка, без расширения допуска.

Только исходный organizer bbox, EXIF-aware RGB, затем официальный LVD preprocessing: ToImage(uint8) → Resize((256,256), bilinear, antialias=True) → ToDtype(float32, scale=True) → ImageNet mean/std. Нет center crop за пределами bbox. Из 261 токена берутся CLS под индексом 0 и среднее 256 patch-токенов начиная с 5; четыре register-токена исключаются.

Camera/vehicle ID нужны только существующему evaluator и проверке разделения; модель их не получает. Имя файла используется только для однозначного открытия изображения. Нет OCR, детектора, маскирования номеров, изменения bbox или новых внешних обучающих фотографий.

## Что сохраняется и что не меняется

Результаты — только `runs/<RUN_NAME>/`: manifest, блоки признаков, проверки, per-system/per-query метрики, `results.json`, `REPORT.md`. Новые веса, кэш и изолированные пакеты исключены из Git. NiVe остаётся локальным и **не нужен D0**.

Старые источники, organizer-данные и активная сборка защищены хешами до и после запуска. Исходные calibration/validation не оцениваются, threshold не подбирается, candidates-policy не меняется. v25 остаётся активным. Здесь не создаётся готовая конкурсная поставка: D0 — ranking-screening. Лимит весов всей будущей сборки и аппаратную скорость потребуется проверить только при переходе к интеграции; 86 МБ одной новой модели сами по себе не подтверждают соответствие всей поставки.

Слабый DINO отдельно не закрывает его полезность в смеси. Но ни один результат не запускает D1/дообучение автоматически — сначала разбираем отчёт. Прежние многочисленные проверки на inner ограничивают силу обобщающих выводов.
