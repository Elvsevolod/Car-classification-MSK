# Проверка реализации D0 · 2026-09-27

**Обновление статуса:** после этих проверок пользователь закрыл DINOv3-ветку из-за отказа в доступе. Рабочий notebook удалён с точной архивной копией; проверка его наличия больше не входит в тесты. Ниже сохранён исторический отчёт подготовки, а не актуальное предложение запуска. Реальных DINO-метрик так и не получено.

## Итог

Notebook готов для запуска пользователем после одобрения доступа к официальным gated-весам и локального входа. **Предобученные веса DINOv3 ещё не скачаны; реальный D0 mAP не измерен.** Тестовые случайные веса не являются результатом эксперимента, лежат только во временных каталогах pytest и не могут пройти production-проверку происхождения.

Добавлены только вариант v35, `training/dino_frozen.py`, `training/dino_experiment.py`, `tests/test_dino_frozen.py`. Старые исходники, данные, bbox, веса, результаты и приложение не изменялись. Commit/push/merge не выполнялись.

## Выполнено

На существующем Python 3.11.9:

```sh
ORT_DISABLE_TELEMETRY=1 .venv/bin/python -m pytest -q tests/test_dino_frozen.py tests/test_retrieval_policy.py tests/test_dual_role_inference.py tests/test_nive_system.py
```

**112 passed in 7.44s**, из них 24 новых D0-проверки. Это время тестов, не скорость DINO на реальном датасете.

Проверены:

- реальная реализация Transformers DINOv3 ViT-S/16, 12 слоёв, 384 признака, 4 register-токена, с созданным во временном каталоге случайным checkpoint;
- локальная загрузка safetensors, реальный encode JPEG/PNG, заблокированная сеть, неизменность параметров/буферов, eval/frozen;
- batch 1/8/16/32, перестановка/удаление изображений и отсутствие зависимости от camera/vehicle/time;
- корректные CLS/patch pooling, исключение registers, официальный tensor-first preprocessing;
- отказ на zero/NaN/неверную размерность, выход bbox за границы, отсутствующее/неоднозначное изображение;
- отказ при повреждении весов/config/license/model card, отсутствие молчаливой замены модели/устройства, обязательность локального входа для скачивания и закреплённая revision в команде;
- формула cosine-смеси 90/10, точные ranking-проверки на искусственных признаках;
- контроллер целиком на искусственных данных: три системы, официальный scorer, неизменные кандидаты существующего runtime в регрессионных тестах, без обучения/калибровки/outer-перехода;
- прерывание, переиспользование завершённого блока, проверка изменённого кэша, неизменность manifest;
- notebook валиден, код всех ячеек компилируется; секреты не запрашиваются в ячейках. Полный Run All до доступа не выполнялся.
