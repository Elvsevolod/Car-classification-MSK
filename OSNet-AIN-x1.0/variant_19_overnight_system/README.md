# Variant 19 — ночная серия улучшений системы

Открой `run_overnight_system.ipynb` в ядре `.venv` проекта, сделай **Restart Kernel → Run All**. По умолчанию включены все реализованные проверки, пять пилотов и автоматическое подтверждение. Само обучение при подготовке notebook не запускалось.

Основание: пользовательские `Car_ReID_system_plan_2026-09-25.md` и `Car_ReID_system_evidence_2026-09-25.md`, проверенные вместе с текущими v16–18. Часть документа описывает старое состояние: hybrid-candidate, ансамбль и checkpoint/rerank-grid уже проверены в v18. Ночью их обучение повторно не запускается.

## Что посчитается

| Направление | Реализация в одном Run All |
|---|---|
| A: runtime | Два заранее выбранных frozen bundle: первый R1 seed и равновесный ансамбль. Полный CPU extractor, 50 прогревов/300 замеров, throughput 1/8/16/32 по 10 с; сумма весов; batch/query-order parity; замороженный полный экспорт трёх файлов на публичном test с раздельными таймерами. Без оценки качества test. |
| B: кандидат отдельно от top-10 | Контроль raw/ranked кандидата, официальный CSV roundtrip. Качество считается только на внутренних encoder-held-out ID. |
| C: предел top-K | Hit@20/50, AP10-oracle с корректным знаменателем; отдельно raw-pool и настоящий reranked-pool локального scorer. |
| D: локальные детали | Frozen conv5 OSNet → 4×4 локальных токена. Два scorer (`mean_best`, `partial`) × K20/50 × добавка 0,05/0,10/0,20 = **12 новых настроек + контроль**. Три seed × три фиксированных primary-эпизода: 117 оценок. Признаки и local scores переиспользуются. |
| E: отказ | Cosine; cosine+margin; single-model cosine+local evidence; ensemble cosine−disagreement. Raw/ranked candidate. Порог на одной группе identity, оценка на другой; функция выбирается на primary и замораживается перед alternate. Отчёт включает F1/TNR/C, coverage и ошибки среди принятых. |
| F: маски | Замороженный локальный выбор и контроль: masked-query, masked-gallery, masked-both на первом primary seed; прежний порог не донастраивается под маску. Автоматический proxy, **не точный аудит номера**. |
| G: перенос ансамбля | R1 student сохраняет CE/SupCon/consistency и сравнивает cosine Gram с тремя замороженными teacher **того же inner fold**, коэффициенты 0,1 и 1,0. Сопоставляется с новым matched R1 control. |
| Предыдущая аналитика: K2 | Классификационный масштаб 1 против √544; retrieval embedding, BN/L2 ветвей и остальные настройки не меняются. |

Пять обучающих пилотов: `R1_control`, `K2_ce1`, `K2_ce_sqrt544`, `R1_kd01`, `R1_kd1`. Каждый начинает со stock, останавливается на **800 optimizer updates**, сохраняя исходный **LR horizon 1700**. Это не 800 эпох. CE, metric/consistency/KD losses, train accuracy, std logits, norm classifier и нормы градиентов CE/metric по общему feature tensor сохраняются в history. Последние не выдаются за нормы градиентов всех параметров.

## Автоматический отбор без ночных вопросов

1. Локальная сетка выбирается по среднему трёх seed/трёх primary-эпизодов. Нужны ≥0,2 п.п. и положительный знак в ≥2/3 seed; иначе остаётся baseline. На alternate только замороженный выбор и baseline.
2. Все пять обучающих пилотов выполняются на первом фиксированном seed. Для дополнительных обучений нужны ≥0,3 п.п. **и относительно контроля семейства, и относительно R1**. По одному кандидату на семейство CE/KD; нет выбора лучшего seed.
3. У кандидатов и необходимых matched controls добавляются два primary seed. Средний парный выигрыш должен быть ≥0,2 п.п. и положительным в ≥2/3 seed. Только тогда обучаются три alternate seed с теми же настройками и шагом.
4. Никакого автоматического outer/final обучения, смены MVP, подбора по исторической validation или автоматического пуша. Gate — фильтр затрат, не статистическое доказательство победы.

Если пилот падает, решение об отборе не замораживается по неполному набору. После повторного Run All оно будет принято по полным результатам. Отрицательный завершённый результат сохраняется как отрицательный, а не пересчитывается до успеха.

## Время и возобновление

`WALL_HOURS = None` — **без общего ограничения времени**, по просьбе пользователя очередь работает до завершения всех запланированных задач и прошедших отбор подтверждений. Ранее R1 800 шагов на этом MPS занимал около 15 минут, но KD добавляет три teacher forward, а локальные признаки/диагностики тоже требуют времени. Полная очередь может работать дольше одной ночи. При необходимости числовой лимит можно включить явно; он не меняет научный manifest.

Очередь последовательная: несколько одновременных обучений на одном MPS/GPU не запускаются. Шаг/ETA выводятся каждые 25 updates. Выполненные задачи защищены SHA256 и пропускаются. Обучение сохраняет optimizer/RNG на исходных границах 200/285/400/600/800; после сбоя повторяется только незавершённый блок. По умолчанию остановки по времени нет. Если явно задать числовой лимит, обучение остановится после сохранения блока, а CPU benchmark/локальная оценка закончат текущую задачу.

Для продолжения: **не менять `RUN_NAME`, не удалять `runs`, Restart Kernel → Run All**. Не редактировать исходный код между частями одной серии. Ошибки отдельного эксперимента записываются, независимые задачи продолжаются; несовпадение manifest/защищённых данных останавливает серию. Компьютер должен оставаться включённым, без сна, с достаточным местом для checkpoint/cache.

`runs/<RUN_NAME>/REPORT.md` — сводка; `results.json` — итог; `progress.json` — задачи; `tasks/<name>/error.json` — traceback. Все новые outputs изолированы и исключены из Git. Исторические notebook с выполненными outputs не очищаются. NiVe остаётся локальным и не участвует в этой серии.

## Что намеренно не названо реализованным/подтверждённым

- Обучаемый local pair-head требует нового OOF mining/training; этот первый пилот использует frozen scorer без обучения головы. DINOv3 не скачивается и не подключается автоматически.
- Точных проверенных plate-only координат и matched-area non-plate контрольной разметки нет. Автоматические маски не доказывают отсутствие зависимости от номера. View/visually-identical-car аннотации не выдумываются.
- Нет переключения исторического приложения на новый bundle до выбора релиза. Frozen export и замер используют один и тот же конкретный bundle; само приложение не меняется.
- На Mac отсутствует RTX A5000/CUDA. Есть отдельный честный CUDA benchmark API с запретом fallback, но GPU dependency lock, офлайн-контейнер, ORT VRAM и официальный GPU-балл здесь **не проверены**. CPU-скорость не пересчитывается в конкурсные баллы.
- Smooth-AP оставлен за пределами первого ночного пакета: в документе это нижний условный приоритет, а не обязательная замена метрики.

## Проверки
