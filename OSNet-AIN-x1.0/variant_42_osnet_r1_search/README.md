# v42 — целевой поиск лучшего OSNet R1

Открыть **search_osnet_r1.ipynb** на основном Mac в существующем окружении
`Car-classification-MSK/.venv`, выполнить **Restart Kernel → Run All**.
Это отдельный эксперимент, а не обновление запущенного v41. Папку V41_Mac_M4
на другом компьютере не заменять во время обучения. Main/MVP_fusion_v25 не меняются.

## Что именно проверяем

Все 18 вариантов начинают с одного **R1_20260915 step800** из primary-fold v16
и нового состояния AdamW. Это целевое продолжение удачного checkpoint, **не новое
обучение с нуля** и не воспроизведение старого LR schedule.

| Ось | Значения |
|---|---|
| Настоящий metric-батч P×K | 16×2, 16×4, 32×2 |
| Loss | CE + SupCon + прежняя consistency; CE + soft-margin triplet + прежняя consistency |
| Peak encoder LR | 0.1 / 0.3 / 1.0 от **исходного R1**: ≈1.194e-5 / 3.582e-5 / 1.194e-4 |
| Вход | 256×256, прежний square crop и аугментации |
| Дополнительные предъявления | 6 400 / 12 800 / 25 600 / 51 200 |

P — число автомобилей в батче, K — число изображений на автомобиль. Это настоящие
32/64 изображения в одном metric-loss; accumulation не подменяет большой батч.
Каждую конфигурацию считаем до конца, без раннего отсева. Бюджеты в точности делятся
на 32 и 64: конечные 1600 либо 800 optimizer updates, но одинаковые 51 200
robust-примеров. Clean-forward для consistency добавляется в каждом варианте.
Разница количества updates логируется и не объявляется устранённой этим сравнением.

Warmup — первые 3200 предъявлений; далее cosine к 2% peak LR на общем горизонте
51 200, без перезапуска при промежуточной оценке. Head LR ×10, weight decay,
SupCon temperature, label smoothing и веса metric/consistency взяты из исходного
`provenance/v16_manifest.json`, **не из десятикратно уменьшенного NiVe-LR**.
Soft-triplet работает по raw-признакам, как существующая реализация TransReID;
изменение масштаба расстояний отдельно в этот опыт не добавляется.
Нет нового gradient clipping, EMA, XBM, GeM, MixStyle или изменения BN-политики.

## Данные и сравнение

Используется уже подготовленная `research_transfer/v41_inputs` как read-only источник
организаторских изображений и четырёх контрольных моделей. Пакет проверяется целиком
по SHA256, включая его NiVe-файлы, но **ни один NiVe-пример не используется в v42**.
Никаких скачиваний или сборки ещё одной копии датасета нет.

740 train-ID; 185 holdout-ID; три исторических query/gallery draw на этих held-out
ID. Это primary-development, не три независимых fold и не outer validation.
Все четыре контрольные модели обучались только на этом train-разбиении.

Пять метрик для каждого из четырёх checkpoints:

1. Самостоятельный raw mAP@10.
2. Самостоятельный less_graph: k1=20, k2=3, λ=.75.
3. Контроль C_primary: B0_208 + три R1_256, веса .5/.5, λ=.5.
4. Добавление кандидата: зафиксированный граф контроля, G2 expert weight .10.
5. Замена **только R1_20260915** внутри C_primary, без увеличения числа encoder;
   сохранены B0=.5 и по 1/6 каждому R1, граф заново строится с λ=.5.

Рабочий v25 на inner не подмешивается: C_primary — сопоставимый аналог состава,
не полный исторический релиз. Замена R1 его исходными признаками обязана точно
воспроизводить контрольные top-10. Выбор — лучший конкретный checkpoint/вариант
системы по среднему трёх draws, включая возможность оставить контроль. Отдельно
сохраняются лидеры standalone raw/graph. Нет усреднения качества по training-seed
или требования сначала доказать стабильность рецепта. Все оценённые веса остаются.

Исходные bbox, validation, evaluator и истории не меняются. На инференсе scorer
видит признаки текущего query и статической gallery; метки нужны только evaluator.
Camera используется лишь существующим train sampler/правилом junk, не моделью.
Пороги, candidates, F1/TNR не оптимизируются. Нет автоматического refit или promotion.
Новый контроль строится на текущем runtime, чужие измерения не выдаются за новый запуск.

## Прогресс, результаты, продолжение

Видны этап, номер опыта из 18, LR, шаг, число предъявлений, условные проходы по train,
loss, прошедшее время и ETA текущего этапа. Общего лимита времени нет; завершение
за одну ночь не гарантируется. На одном устройстве — одно обучение одновременно.

Результаты: `runs/r1_search_v1/REPORT.md`, `results.json`, `selected_candidate.json`
(только при полном завершении), `trials/*/history.json`, четыре checkpoint/feature
матрицы с порядком image-ID и per-query AP/top-10/delta. История MPS-memory — редкие
замеры allocator, не точный пик и не вся RAM. FP32, без AMP/CPU fallback.

Сохранение optimizer — каждые 100 шагов и на каждой границе оценки. Два чередуемых
resume-файла защищены SHA. Для продолжения: **Restart Kernel → Run All**, тот же
RUN_NAME, без изменения кода/конфига. История считается только из проверенных этапов.
OOM/нечисловой loss записываются как failed trial, остальные конфигурации продолжаются;
batch/LR/precision автоматически не уменьшаются. Повреждённые файлы, смена manifest
и нехватка места останавливают запуск, а не обходят проверки.

Компактный `r1_search_v1_analysis.zip` создаётся автоматически и содержит отчёты,
не бинарные веса. **Не удалять runs:** там лучшие модели для последующего внедрения.
Полный дублирующий ZIP специально не создаётся, чтобы не расходовать диск.
Перед запуском нужно минимум 3 GiB свободного места, желательно 5–6 GiB или больше;
по ходу работы сохраняется резерв 1 GiB. Никакие файлы для освобождения места не удаляются.
В терминале `caffeinate -i` удержит Mac от автоматического сна, пока окно открыто.

CLI из корня проекта, как альтернатива notebook:

```bash
ORT_DISABLE_TELEMETRY=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=4 \
PYTORCH_ENABLE_MPS_FALLBACK=0 PYTORCH_MPS_FAST_MATH=0 \
  .venv/bin/python -m training.osnet_r1_search --device mps
```

Новый вариант не реализует ConvNeXt, полное/частичное размораживание или отдельный
внешний датасет: это следующие гипотезы после этой ограниченной матрицы.
