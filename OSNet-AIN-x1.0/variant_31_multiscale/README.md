# v31 — multi-scale OSNet

Запуск: `search_multiscale.ipynb`, **Restart Kernel → Run All** в прежнем research `.venv`.
Нужны завершённый v30 `pool_rerank_v1` и его локальные неизменные источники.
Нового датасета, скачивания моделей или обучения нет. MVP остаётся на v25.

## Гипотеза

v30 не дал выигрыша: ограничение пула отбрасывало и полезные находки графа.
Здесь меняется информация на входе поиска: извлекаем признаки тех же трёх R1
при 320/384 px вместо одного 256. Это не повтор flip-TTA, power, local scorer
или подбора состава ансамбля. В просмотренной истории такой опыт не найден.

Большее разрешение может сохранить детали крупного исходного crop, но не создаёт
отсутствующей визуальной информации. Модели обучались на 256: перенос на больший
размер также может ухудшить признаки. Поэтому это проверяемая гипотеза, не обещание.

| Вариант | Размер дополнительного R1 | Доля внутри R1 |
|---|---:|---:|
| V25_control | — | 0% |
| r1_s320_w25 | 320 | 25% |
| r1_s320_w50 | 320 | 50% |
| r1_s384_w25 | 384 | 25% |
| r1_s384_w50 | 384 | 50% |

Общая доля MVP/R1 неизменна: 50/50. Векторы конкатенируются с коэффициентами
sqrt(0.5), sqrt(0.5*(1-w)), sqrt(0.5*w); затем L2. Это смесь cosine-оценок
исходного MVP, исходного R1 и R1 большего разрешения. Граф остаётся 20/3/λ0.50
на всей статической gallery. Никакого ограничения raw top-K из v30 не переносится.
Кандидат, confidence и порог — только из первоначального R1_256.

## Что именно меняется в модели

В локальных R1 ONNX есть GlobalAveragePool и нет внутренних фиксированных
описаний spatial shape. В копиях модели в памяти меняется только объявленный
H/W входа; проверяется ONNX full_check и побайтовая неизменность всего остального
после обратной подстановки 256. Операторы, веса, константы и BN не изменяются.
Исходные ONNX-файлы не перезаписываются. Каждый размер проверяется на batch 1 и 3;
на реальных изображениях отдельно сравниваются batch 1 и рабочий batch.
Исходный 256-проход обязан совпасть с прежним кэшем в прежнем допуске 2e-5.
Допуск не увеличивается ради успешного теста.

Предобработка прежняя: EXIF/RGB, исходный organizer bbox, bilinear square resize,
ImageNet normalization. Не меняются bbox/метки и не удаляются сложные примеры.
Нет OCR, выделения номерной зоны или восстановления деталей. Отсутствие остаточного
сигнала номера не доказано. Правила организаторов: вопросы 8 (размерность),
9–10 (независимые query и TTA одного изображения), 16 (общий лимит весов).
Это эксперимент качества, не подтверждение полной готовности конкурсной поставки.

## Порядок проверки

1. Тесты компонентов и preflight завершённого v30/исходных весов.
2. Контроль v25 на calibration, признаки 320 и 384 для query и gallery, четыре сравнения.
3. Выбор максимального calibration mAP среди пяти вариантов; точное равенство оставляет v25.
4. Validation: контроль плюс один замороженный выбор. Только выбранное новое
   разрешение извлекается на validation. Если победил v25, этот проход пропускается.
5. Экспорт, повторение решений по NPY, парные изменения AP и итоговый отчёт.

Оба split уже наблюдались. Это адаптивный development-поиск, не независимая
оценка скрытого теста. Нет обучения на validation, подбора порога или автопродвижения.

## Сохранение и стоимость

Новый каталог `runs/multiscale_v1`: manifest, frozen_selection, results.json,
REPORT.md и task-каталоги. Извлечение сохраняется каждые 128 изображений,
batch 16, CPU-only, без скрытого переключения provider и без лимита времени.
Повторный Run All проверяет контрольные суммы и продолжает с готовых блоков.
Изменённый кэш останавливает запуск, не заменяется молча. Ошибка одной calibration
ветки не мешает второй, но выбор и validation требуют всех пяти готовых сравнений.

Для контроля сохраняются прежние 2048 признаков. Для нового варианта — реальные
3584 = original2048 + high_resolution_R1_1536, query затем gallery в исходном порядке.
Кандидаты побайтно совпадают с v25; отказы не удаляют top-10 из submission.csv.
Неоднозначность junk/top-10 остаётся; evaluator не меняется.
Дополнительный проход трёх encoders дороже v25; время очереди не выдаётся за
официальный замер скорости. Производительность и интеграция — отдельный этап при выигрыше.

Код inference не импортирует обучение. Эксперимент изолирован согласно
karpathy-guidelines: новый каталог, фиксированная сетка, проверяемые ограничения,
без рефакторинга или изменения защищённых старых модулей. Исправлен только тест
повторного запуска v30: сохранённые outputs notebook больше не считаются ошибкой.
