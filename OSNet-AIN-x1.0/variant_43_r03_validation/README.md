# v43 — один сохранённый checkpoint R03 против рабочего v25

Открыть `validate_r03_vs_v25.ipynb` в **основном Car-classification-MSK**, выбрать
ту же проектную `.venv`, что использовалась для v42: **Restart Kernel → Run All**.
Новые зависимости, внешние датасеты, скачивания и обучение не нужны.
По умолчанию используется MPS без CPU fallback. В notebook видны этапы,
число обработанных изображений и время завершения каждого этапа. Лимита времени нет.

## Что именно сравнивается

Один заранее выбранный checkpoint v42:

- `R03_p16k2_supcon_lr1`, **step400**, **12800** дополнительных предъявлений;
- SHA256 `0b442bb7ce7f8f922671e15d5e3f2ed343f8c3dab53a93b9111564a78e6cd20a`;
- это конкретные сохранённые веса, обученные на 740 train-ID, без refit;
- последний step1600 не используется и другие checkpoints здесь не оцениваются.

Контроль — фактический `MVP_fusion_v25`, а не C_primary из v42. Порядок seed
и checksums исследовательских/поставленных моделей сверяются с соседней
`Car-classification-MSK-main`. Используется прежний проверенный v25-кэш;
он не выдаётся за новый замер скорости. Небольшой fresh-image probe проверяет
его соответствие весам. Весь контрольный `submission.csv` и `candidates.csv`
должны воспроизвестись побайтно.

Ranking кандидата: MVP208 вес .5 + equal3(R03, full-train R1_seed16, R1_seed17) вес .5.
Граф строится заново по статической gallery: **k1=20, k2=3, lambda=.5**.
Модель не получает camera/vehicle ID, время, координаты камеры или имя изображения.
BBox и preprocessing не меняются. Метки используются только при подсчёте метрик.

**Кандидатский режим остаётся исходным full-train R1_equal3 v25**:
raw_top1, cosine-confidence, threshold **0.534365177154541**. Исходный seed15
поэтому тоже нужен: всего **5 энкодеров вместо 4**. Это не бесплатное улучшение
по скорости. Его будущие затраты и ONNX-поставка здесь не проверяются.

## Validation и границы вывода

Только исходные **309 query / 896 gallery**; 247 known и 62 open-set query.
Разбиение не создаётся заново. Проверяются identity-disjointness обучения,
внутреннего выбора v42 и исходной validation, байты изображений и разметки.
NiVe-изображения, тестовые изображения организаторов и calibration не используются.
`research_transfer/v41_inputs/inputs.json` нужен только для происхождения весов;
`v41_inputs.zip` не нужен.

Здесь **нет** перебора seed, weights, lambda, thresholds, BN adaptation, optimizer
или выбора по validation. Сравниваются только контроль и один зафиксированный
кандидат. Original validation уже наблюдалась в истории экспериментов: это
проверка переноса на рабочую систему, а не новый независимый hidden test.
Различие между прежними primary-моделями и full-train компонентами MVP явно
сохраняется; результат v42 0.85215 не переносится в итоговую таблицу как факт.

## Что делает Run All

1. Компонентные тесты и preflight: pinned v42/v25, модель, данные, устройство.
2. Малый probe: реальные изображения R03 против сохранённых v42-признаков,
   реальные изображения v25 против старого кэша. Допуск 2e-5, не расширяется.
3. Извлечение R03 на validation в eval/inference-mode; проверка неизменности BN.
4. Общий scorer и два экспорта: top-10, неизменные кандидаты/отказы, реальные NPY.
5. Точный replay NPY/CSV, per-query AP/top-10, парный bootstrap по автомобилям,
   проверка защищённых источников, итоговый отчёт и компактный архив.

Синтетические тесты проверяют перестановку/удаление соседних query, batch 1/8/16/32,
повреждённый кэш, недоступное устройство, полный отказ с сохранением десяти ID,
атомарность этапа и возобновление без повторного извлечения. Bootstrap —
описательная оценка неопределённости, не автоматическое условие продвижения.

## Файлы и продолжение

Новый каталог `runs/validation_v1/`: `manifest.json`, `frozen_candidate.json`,
`results.json`, `REPORT.md`, признаки и два каталога с конкурсными файлами.
У контроля NPY имеет 2048 координат; у кандидата **2560 float32**:
MVP512 + исходный R1_equal3_1536 + R03_512. Это реальные блоки эмбеддингов;
их точные роли сохранены в `embedding_order.json`. Нормализация поблочная,
не глобальная. Изображения не пропускаются, выдуманных векторов нет.

Каждый query сохраняет десять различных gallery-ID даже при отказе;
отказ — отсутствие строки в `candidates.csv`. Junk обрабатывает только исходный
evaluator: расширенный ranking не сдаётся и метки не используются для фильтрации.

`validation_v1_analysis.zip` содержит отчёты/CSV, но не веса и не NPY.
Для продолжения: **Restart Kernel → Run All** с тем же RUN_NAME и неизменным кодом.
Готовые этапы проверяются по SHA256. Незавершённый этап пересчитывается целиком;
результат публикуется атомарно. Нужно минимум **1 GiB** свободного места.

MVP, v41 на другом компьютере, исходные веса, bbox, исторические runs не меняются.
Автоматического продвижения, Git commit/push, нового архива датасетов нет.
Не переносить изменённые исследовательские исходники поверх работающего v41.
