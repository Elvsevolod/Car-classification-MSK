# v21 — лучшая конкретная модель, а не самый стабильный рецепт

Открой `search_best_model.ipynb` в прежнем исследовательском `.venv` проекта
Car-classification-MSK: **Restart Kernel → Run All**. Источники — завершённые
`review_v1`, `policy_v1`, `quality_v1`. Интернет и другое устройство не нужны.

## Что выполнится

1. Проверка данных, source/weights/cache SHA256 и общего primary-разбиения.
2. Извлечение/чтение признаков 13 конкретных encoder: R1 step800 × 3 seed,
   full1700 / full1700+BN / average1400-1600-1700+BN × 3 seed, cosine800 × 1 seed.
   Два недостающих average создаются в новом run; BatchNorm видит только train.
   Новых optimizer updates нет. Готовые веса v20 не переписываются.
3. 20 сравнений при λ=0.75: 13 одиночных encoder, исходный equal3 и 6 уже
   обученных pair-head (0.05/0.10 × 3 seed). Head привязан к своему R1 step800,
   не переносится автоматически на новые веса и не становится частью embedding-ансамбля.
4. Лучший новый одиночный encoder участвует в пяти фиксированных ансамблях:
   замена каждого из трёх R1; добавление с весом 0.10 / 0.25. Остальные веса равны.
   Косинусное объединение: L2-normalized sqrt-weighted concatenation, не сумма координат.
5. Equal3 и две лучшие другие конфигурации сравниваются с λ=0.75/0.50/0.65/0.85,
   k1=20, k2=3. Вместе — 34 уникальные конфигурации × 3 одинаковых query/gallery
   эпизода; плюс повтор выбранного варианта для диагностики candidate-режима.
6. Сохранение таблицы всех результатов, точного состава, весов, источников
   checkpoints, top-10, raw-кандидатов и confidence. Исторические mAP контролей
   должны воспроизвестись с фиксированным допуском, иначе запуск останавливается.

**Отбор:** максимальный средний mAP@10 одной конкретной системы по трём одинаковым
primary-эпизодам. Не среднее по seed, не требование выигрыша 2/3 seed, нет минимального
прироста .002/.003. При точном равенстве остаётся ранее перечисленная конфигурация
(исходный equal3 и λ0.75 имеют приоритет). Не выбираем победителя по неполному набору.

## Результаты и возобновление

`runs/search_v1/REPORT.md` — таблица и вывод; `results.json` — подробные метрики;
`selected_candidate.json` — конкретные модели/веса/λ; `tasks/*/*.npz` — признаки
либо настоящие top-10 и raw-кандидаты. Это исследовательский manifest, не готовый
конкурсный bundle. Порог в нём `null`: чужой threshold не переносится на новый ансамбль.

Общего ограничения времени нет. Печатаются этап, конфигурация, прогресс по
изображениям/BN-батчам, mAP каждого эпизода и время. Задачи последовательны.
Повторный Run All с тем же `RUN_NAME` проверяет SHA256 готовых задач и продолжает
незавершённые. Не удаляй старые outputs и не редактируй код посреди запуска.
При изменении кода/плана нужен новый `RUN_NAME`. Включи питание и отключи сон.

## Честные границы

- Это новый поиск на уже исследуемой внутренней выборке. Выбранный максимум
  может быть оптимистичен; он не объявляется независимым подтверждением или
  ожидаемой метрикой скрытого теста. «Стабильность рецепта» не блокирует выбор весов.
- Primary checkpoints обучались на 740 train identity, а не на полном train.
  Их нельзя напрямую проверять на alternate: там могут оказаться знакомые им identity.
  Перенос выбранного состава в full-train/экспорт — отдельное решение после анализа.
- Raw top1 и cosine-confidence отделены от reranked top-10. Для победителя F1/TNR/C
  считаются на разных внутренних identity калибровки/оценки; это диагностика, не
  критерий ранжирования, не независимая оценка всей системы и не финальный порог.
- Исходная validation, bbox, изображения, старые runs, MVP и release-integration
  не меняются. Нет нового обучения головы/encoder, внешних данных, OCR, plate-масок,
  детекции, camera/time/ID признаков в scorer, Docker/GPU benchmark и автопродвижения.
  NiVe остаётся локальным и не участвует. Push/merge не выполняются.
- Oracle не используется в отборе. Официальная семантика junk/top-10 не меняется:
  десять ID до фильтрации evaluator. Query обрабатываются независимо.
