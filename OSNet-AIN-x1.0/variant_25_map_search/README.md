# v25: mAP при фиксированном кандидатском режиме v24

`search_map.ipynb` → прежний research `.venv` → **Restart Kernel → Run All**.
Лимита времени нет, интернет/GPU не требуются. Обучения и повторного encoder inference нет.
Используются проверенные признаки MVP и **full-train R1 v18** из завершённых v22/v24.
Это не повтор v23: там смешивался MVP с primary v21, а здесь full-train R1 и меняется только ranking.

84 заранее зафиксированных сравнения:

- 72 варианта MVP: k1=10/20/30/40 × k2=1/3/6 × λ=0.25/0.40/0.50/0.65/0.75/0.90;
- 12 смесей: доля R1=0.10/0.25/0.50 × λ=0.40/0.50/0.65/0.75 при k1=20, k2=3.

Первым идёт текущий MVP 20/3/0.50. Выбор по **calibration mAP@10**, при точном равенстве
побеждает первый вариант. На validation проходят только исходный v24 и один выбранный вариант.
Кандидат, его confidence, отказы и порог 0.534365177154541 всегда берутся из исходной R1-ветки.
Не добавляются правила согласия с top-10: на calibration они отбрасывали правильные ответы.

Ranking-смесь — L2(concat(sqrt(1-w)×MVP, sqrt(w)×R1)), без сложения разных координатных пространств.
Признаки в итоговом export остаются настоящими 2048-мерными блоками v24: MVP512 + R1_1536.
Параметры ranking записаны в embedding_order.json; повторный расчёт из NPY обязан вернуть те же решения.
submission.csv сохраняет десять разных ID при любом отказе, candidates.csv побайтно совпадает с v24.

Выбор, результаты и отчёт: `runs/map_search_v1/`. Прерванный запуск возобновляется с тем же RUN_NAME.
Чтобы заново пересчитать всё, используй новое имя запуска. Старые runs не удалять и не редактировать.
При несовпадении исходников/артефактов запуск останавливается, пороги и допуски не изменяются.

Тесты notebook используют синтетические данные. Исторические bbox, validation, веса, чужие изменения
и MVP-приложение не трогаются. Автоматического продвижения победителя нет.
Это поиск на уже наблюдавшихся development-данных, не независимое подтверждение hidden-test качества.
Победитель calibration может проиграть validation; тогда текущий v24 сохраняется.
