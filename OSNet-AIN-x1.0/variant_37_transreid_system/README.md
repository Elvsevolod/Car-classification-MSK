# v37 — MVP_fusion_v25 + сохранённый TransReID

Открыть `compare_transreid_system.ipynb`, выбрать `.venv` проекта и **Run All**.
По умолчанию `DEVICE='mps'`, `RUN_NAME='system_v1'`. Нового обучения и скачивания нет.
Нужен завершённый локальный `variant_36_transreid_night/runs/night_v1` и прежние артефакты v24/v25.
Ноутбук работает на текущей структуре research/main; это не автономная поставочная сборка.

1. Проверка компонентов, контрольных сумм, train/outer разделения и сохранённых весов.
2. Свежая проверка воспроизведения v25-кэша; T12/T22 — batch 1/8/16/32, перестановка и одиночное изображение.
3. Calibration: v25 плюс T12 и T22 с долями 5/10/15/20% — **девять систем**.
4. Фиксация одной системы по максимальному calibration mAP@10. При точном равенстве: контроль, меньшая доля, T12.
5. Исходная validation: только контроль и зафиксированный победитель. Если выбран контроль, сравнивать больше нечего.
6. Экспорт трёх файлов, replay, проверка неизменности candidate CSV и итоговый отчёт.

T12: `T12_global_supcon/step_01800.pt`, 384D. T22: `T22_jpm_supcon/step_01800.pt`, 1920D.
До графа: `(1-w)*cosine(v25) + w*cosine(TransReID)`; v25 сохраняет равные доли MVP и R1 equal3.
Граф **legacy k1=20, k2=3, lambda=.50**. Никакого перебора графа, порога или validation.
Кандидат, confidence, порог **0.534365177154541** и отказы — прежние v25/R1 equal3.
T12/T22 вместе в одной системе не смешиваются в этом этапе.

Результаты: `runs/system_v1/REPORT.md`, `results.json`, `frozen_selection.json` и
`tasks/export_<split>_<system>/export/{submission.csv,candidates.csv,embeddings.npy}`.
Числа в последней ячейке и отчёте — результаты этого запуска, не старые inner-метрики.
Размерность банка: контроль 2048, с T12 2432, с T22 3968. Это реальные unit-блоки с описанными slices,
а не единый cosine-вектор: ранжирование и отказы используют разные ветви.

Повторный Run All проверяет и переиспользует законченные этапы, не выдавая кэш за новый замер скорости.
Незаконченный этап повторяется; параметры, код, устройство или исходные файлы нельзя менять под тем же именем запуска.
Этапы публикуются атомарно, повреждённый кэш вызывает ошибку. Ограничения времени нет; нужен минимум 1 GiB свободного места.
Веса не копируются, исторические результаты не изменяются, NiVe не требуется.

Это исследовательское сравнение качества сохранённых checkpoints на 740 train-ID, не full-train refit.
Обе исходные development-выборки уже использовались раньше — результат не является независимой оценкой hidden test.
Новый encoder работает в PyTorch float32; v25 — проверенный CPU ONNX-кэш. Это не новый готовый ONNX-профиль продукта.
Проверки скорости/GPU/Linux и перенос в продукт — отдельный этап при полезном выигрыше.
`main`, рабочий `MVP_fusion_v25`, bbox и исходная validation не меняются. Автоматического promotion нет.
