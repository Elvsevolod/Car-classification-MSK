# v33 — один сопоставимый повтор N0/N1 с auxiliary 0.025

Запуск: `train_nive_low_aux.ipynb`, проектный `.venv`, **Restart Kernel → Run All**. Уже выставлены `RUN_NAME='low_aux_v1'`, `DEVICE='mps'`. Нужна та же среда, что в завершённом v32. Если она изменилась, preflight останавливается, а не переключает устройство молча. Полное обучение запускает пользователь; лимита времени нет.

Проверка реализации: [IMPLEMENTATION_CHECKS.md](IMPLEMENTATION_CHECKS.md) — 130 тестов, короткий MPS-прогон обеих ветвей и точное воспроизведение N_ref. Полный quality-run не запускался.

## Одна гипотеза

В v32 NiVe при auxiliary-весе 0.25 ухудшил mean inner mAP: лучший N1 — update0; финальный — 0.831807 против исходного 0.844099. Нормы weighted auxiliary-градиентов в ряде замеров были в 2–3 раза больше main. Последние 200 target-only updates частично восстановили качество. Это мотивация проверить более слабый внешний сигнал, не доказательство единственной причины падения.

Меняется **только `L_main + 0.25 L_aux` → `L_main + 0.025 L_aux` в обеих ветвях**. Это сравнение одинаковых условий, поэтому N0 также обучается заново. Сравнивать новый N1 только со старым N0 было бы недостаточно.

- Тот же R1 primary/seed20260915/step800, 740 train identity и 185 inner holdout; не full-train encoder v25 и не финальный N0/N1 из v32.
- Те же main и auxiliary индексы, per-update seeds аугментаций, отдельные train-only головы и domain-local SupCon. Проверяются fingerprints расписаний и строк NiVe.
- Те же численные LR/decay/warmup/scheduler, preprocessing и BN: auxiliary robust первой, main второй, один optimizer step; clean views eval/no_grad.
- По 1600 joint + 200 target-only updates; 108800 логических предъявлений на ветвь, 217600 clean/robust image-forwards. N1: 57600 organizer + 51200 NiVe. Используется только NiVe train; source test и маски не участвуют в loss.
- Точки 0/400/800/1200/1600/1800, три прежних primary draws; raw и фиксированный graph 20/3/0.75, per-query AP/top-10. Выбор конкретного checkpoint по mean graph mAP, при равенстве более ранний.
- Ровно две прежние 50/50 смеси с N_ref после single-отбора. Нового поиска graph, fusion weights или threshold нет.

**BN не замораживается.** Вес loss не влияет на частоту обновления running stats. Если результат снова отрицательный, это не позволяет автоматически объявить BN единственной причиной. После этого адресного повтора новая сетка коэффициентов не запускается автоматически.

## Изоляция и проверки

Код и артефакты v32 не редактируются. Переиспользуются его функции training, loss, resume, evaluation и head-free export, а не его orchestration с зашитым 0.25. Новая orchestration применяет коэффициент из нового плана и в smoke, и в полном обучении. Resume использует прежние два слота и атомарный указатель каждые 100 updates.

Проверяются точные hashes manifest/results v32, исходники и защищённые изображения/аннотации/веса v25. История `v32/runs/pilot_v1/` дополнительно защищается целиком. Сохранённый dHash-аудит переиспользуется после повторной проверки его fingerprint; нового визуального осмотра это не означает. Не требуется повторно запускать notebook v32.

До полного обучения свежие N_ref признаки, порядок и метрики должны точно совпасть с v32. Стартовые точки обеих новых ветвей также равны N_ref. Допуски ONNX остаются прежними: atol 2e-5, rtol 0; heads в экспорт не входят. Smoke — отдельные три update/ветвь с коротким техническим scheduler, не часть качества/бюджета пилота.

## Что читать после Run All

`runs/low_aux_v1/REPORT.md` и `results.json`: N_ref/N0/N1, все checkpoint, фиксированные смеси и **сравнение с первым опытом 0.25**. `comparison_to_v32` содержит разницы на одинаковых шагах и per-query сравнение выбранных решений. Loss/градиенты/BN — `training/*/history.json`.

`continue` — только положительный screening против нового matched control. Для выбора итоговой модели также надо смотреть сохранённый лучший N0/800 и его смесь из v32 (0.845909). Ухудшившийся контроль не делает новый результат лучшим в истории. Если выбран N1/0, экспорт не содержит эффекта NiVe и смесь фактически сочетает две копии parent.

Рабочий v25, bbox, исходная validation, порог, evaluator и прежние runs не меняются. Автоматического promotion, нового full-refit, публикации NiVe, push или merge нет. Этот inner-опыт не является оценкой скрытого теста или GPU-приёмкой.
