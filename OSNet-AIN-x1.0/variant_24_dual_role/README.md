# v24 — MVP для top-10, full-train R1 для кандидата

Запуск: `verify_dual_role.ipynb` → прежний `.venv` → **Restart Kernel → Run All**.
Интернет, GPU и другое устройство не нужны. Общего ограничения времени нет.
Результаты: `runs/dual_role_v1/REPORT.md`, `results.json`, `dual_role_profile.json`.

Это проверка одной фиксированной системы, без обучения, новой калибровки или перебора.
Исходный MVP, приложение, веса, bbox, validation и предыдущие runs не изменяются.
Данные уже использовались при исследованиях: это development-проверка, не независимый тест.

## Фиксированные роли

| Часть | Источник | Настройки |
|---|---|---|
| Top-10 | MVP, 208 / 512 | legacy, k1=20, k2=3, λ=0.50 |
| Кандидат и confidence | full-train R1 equal3 v18, 256 / 1536 | raw_top1, максимальный cosine R1 |
| Отказ | тот же R1 | сохранённый порог 0.534365177154541; берётся из bundle, не подбирается |

R1 less_graph-реранкер не участвует в новом inference: raw-кандидат от него не зависит.
Порог MVP для top-10 не нужен; старый профиль MVP сохраняется без изменений.
Confidence привязан к R1-кандидату, который может отличаться от первого результата MVP
и даже находиться вне top-10 MVP. Кандидатский режим оценивается отдельно (Q&A №13–14, №31).

Настоящий `embeddings.npy`: float32, query затем gallery, 2048 столбцов.
Столбцы `[0:512]` — исходные единичные MVP-векторы, `[512:2048]` — единичные R1-векторы.
Общая норма sqrt(2); дополнительной нормализации нет, чтобы не менять точность исходных блоков.
Общая L2-нормализация не обязательна (Q&A №8). Эталонная cosine-метрика всего вектора
не описывает финальный ranking: финальные решения воспроизводятся через разделение ролей.

## Что делает Run All

1. Синтетические тесты, в том числе настоящий ONNX-инференс, JPEG/PNG, границы bbox,
   повреждённые веса, запрет CUDA fallback, отказ с сохранением top-10, независимость query.
2. Read-only preflight завершённого `v22/comparison_v1`: checksums весов, кода, данных,
   протоколов и сохранённых решений. Фиксация нового профиля до вычисления метрик.
3. Экспорт на сохранённых calibration-признаках; точное воспроизведение компонентов,
   проверка R1-кандидатов при старом пороге. **Нового подбора порога нет.**
4. Экспорт на сохранённых validation-признаках. `submission.csv` должен побайтно совпасть
   с `v22/MVP_active`, `candidates.csv` — с `v22/R1_equal3_full_v18`.
5. Новый проход по всем исходным validation-изображениям через четыре ONNX encoder,
   batch16, единый scorer и экспорт. Повторная проверка CSV (строго) и признаков
   (заранее установленный max abs ≤2e-5). Допуски не расширяются ради успеха.
6. Отчёт, проверка неизменности исходников и артефактов. Никакой автоматической замены MVP.

Для каждого этапа сохраняются три конкурсных файла и `embedding_order.json`.
Это validation-экспорты, не файлы скрытого теста. Во всех `submission.csv` ровно десять
разных gallery-ID для каждого query; отказ — отсутствие строки в `candidates.csv`.
Ограничение junk/top-10 сохраняется: исходный evaluator не изменяется.

Этапы сохраняются атомарно и возобновляются с тем же `RUN_NAME`. При повторном запуске
готовые этапы отмечены `CACHED` — это не новое измерение скорости. Если нужен полностью
новый прогон, задай новое имя, например `dual_role_v2`. Не удаляй старые результаты.
Несовпадение checksums или решений останавливает запуск; не редактируй пороги для обхода.

## Один автономный экспорт

После preflight профиль можно использовать из корня репозитория:

```bash
.venv/bin/python -m training.dual_role_inference \
  --profile OSNet-AIN-x1.0/variant_24_dual_role/runs/dual_role_v1/dual_role_profile.json \
  --dataset /absolute/path/to/test_dataset \
  --output /absolute/path/to/new_export \
  --batch-size 16
```

В dataset нужны только `test_query.csv`, `test_gallery.csv` и `images/`.
CSV: `image_id,x,y,w,h`; метки не нужны, train/calibration CSV не читаются.
Изображения — JPEG/PNG с однозначным именем по ID. Нет БД, сети, torch и обучения
в этом runtime. Профиль содержит ссылки на существующие веса, поэтому нельзя переносить
один JSON без соответствующих ONNX/bundle-файлов. Это CPU-прототип, не полная поставка.

## Как читать результат

Ожидание по v22: сохранить mAP@10 MVP **0.8146886982** и получить C R1 **0.7697214076**.
Это улучшение кандидатского режима, не новый рекорд ranking. F1 растёт, но TNR снижается:
показывать оба показателя, а не только общий балл. `45×mAP+10×C` — два компонента из 55,
не полный конкурсный балл. Преимущество на скрытом тесте и скорость не доказаны.
Проверки GPU/Linux, остаточного номерного сигнала и упаковка поставки остаются отдельными.
