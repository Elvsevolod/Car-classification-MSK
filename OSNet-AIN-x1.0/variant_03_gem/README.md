# Вариант 3: геометрия входа и GeM

## Статус

Сравнение геометрии и полное обучение AvgPool/GeM завершены.
GeM отклонён, активные веса MVP не изменены.

## Подэтап 3.1 — square против letterbox

Один и тот же checkpoint варианта 2 проверен без обучения. Порог отказа подбирался
только на calibration, validation использовалась для сравнения. В обоих случаях
применялся зафиксированный потоковый реранкинг `k1=20`, `k2=3`, `lambda=0.5`.

| Геометрия | mAP@10 | Candidate F1 | TNR | Candidate score |
|---|---:|---:|---:|---:|
| Square `208×208` | **81,47%** | **72,86%** | **79,03%** | **74,71%** |
| Letterbox `208×208` | 66,76% | 67,33% | 66,13% | 66,97% |

Победитель — `square`. Letterbox сохраняет пропорции, но меняет распределение входа
для уже обученной на square-кропах модели. Поэтому GeM проверяется только с прежним
square resize: две гипотезы не смешиваются.

Полные числа сохранены в
[`results/preprocessing_ablation.json`](results/preprocessing_ablation.json).

## Результат обучения

| Pooling | Mean mAP@10 | Std | Mean Candidate score |
|---|---:|---:|---:|
| AvgPool | **0.800250** | **0.005829** | **0.757405** |
| GeM | 0.791110 | 0.007347 | 0.733111 |

GeM уступил контролю и по retrieval, и по качеству отказа. Даже
контрольное дообучение AvgPool не превзошло текущий активный checkpoint
MVP с mAP@10 `0.814689`. Поэтому веса этапа 3 не подключены к backend.
Полные запуски сохранены в
[`results/pooling_ablation.json`](results/pooling_ablation.json).

## Подэтап 3.2 — честная проверка GeM

Ноутбук запускает две группы из одного и того же `best_map.pt` варианта 2:

- контроль: обычный global average pooling;
- эксперимент: generalized mean pooling с обучаемым `p`, начальное значение `3.0`.

Каждая группа обучается с seed `20260915`, `20260916`, `20260917`. Остальные
настройки наследуются от победителя HPO: `P=16`, `K=2`, BNNeck, SupCon, раздельный
learning rate и прежние аугментации. Максимум — 15 эпох; early stopping разрешён
после шестой эпохи при отсутствии улучшения mAP четыре эпохи подряд.

Для каждого seed берётся checkpoint с лучшим raw mAP, после чего он дополнительно
оценивается с активным потоковым реранкингом. Победитель выбирается по среднему
reranked mAP трёх seed. Вариант не допускается к выбору, если его средний Candidate
score ниже AvgPool более чем на 0,5 процентного пункта. Для ONNX берётся не самый
удачный seed, а запуск, ближайший к среднему результату победившей группы.

## Запуск

Из корня репозитория:

```bash
.venv/bin/python -m jupyter lab
```

Открыть `train_osnet_gem.ipynb` и выполнить `Run All`. Обучение использует MPS,
если он доступен. После прерывания повторный запуск продолжит незавершённый seed из
`last.pt` и `history.json`; уже завершённые seed пропускаются.

Результаты появятся в:

- `results/<pooling>_seed_<seed>/history.json`;
- `results/<pooling>_seed_<seed>/summary.json`;
- `results/pooling_ablation.json`;
- `results/export_summary.json`.

Веса сохраняются в `weights/` и исключены из Git. Новый ONNX не подключается к MVP
автоматически: сначала нужно проанализировать среднее и разброс трёх seed.
