# Variant 15: NiVe1303 → OSNet

Первый этап работы с NiVe: **изолированный перенос обучения**, а не одновременный перебор
масок, смешанного обучения и архитектур. Точка входа — `train_nive_transfer.ipynb`.
Полное обучение запускает пользователь. Текущий GeM/MixStyle run и его исходники не изменяются.

## Запуск

1. Дождаться окончания variant 14. Новый запуск проверяет его существующие lock-файлы
   только для чтения и останавливается, если обучение ещё работает.
2. Открыть `train_nive_transfer.ipynb` в прежнем `.venv`.
3. Проверить ссылку `SOURCE_URL`. Если локальная копия действительно взята с официальной
   страницы NiVe1303 v1, установить `SOURCE_CONFIRMED = True`. Подтверждения источника от
   пользователя пока не было, поэтому значение по умолчанию — False. Если использовалось
   другое зеркало/версия, сначала проверить и зафиксировать этот источник, не обходить guard.
4. Оставить `PHASE = 'pilot'`, `RUN_NAME = 'nive_pilot_v1'`; **Restart Kernel → Run All**.
5. Передать для анализа `runs/nive_pilot_v1/PILOT_RESULTS.md` и `pilot_summary.json`.

Пилот — один seed, три условия, **5 стадий / до 6800 optimizer updates**.
Он не оценивает исходную outer validation, не экспортирует и не заменяет MVP.
Порог и поисковые параметры на пилоте не подбираются.

После анализа пилота можно установить `PHASE = 'confirm'` с тем же RUN_NAME и всеми остальными
настройками. Завершённые стадии будут прочитаны без повторных optimizer steps. Этот режим
выполняет до **31 уникальной стадии / 44 200 updates суммарно, включая пилот**.
По умолчанию он не включён. Это существенно дольше первого запуска.

После прерывания: Restart Kernel → Run All. Последний незавершённый блок до 200 шагов
повторится; состояние optimizer восстанавливается из `last.pt`. Изменение кода, данных,
бюджета, seed или runtime требует нового RUN_NAME. PHASE переключать можно.
Не запускать две серии одновременно. CPU-обучение в notebook заблокировано по умолчанию.

## Что сравниваем

| Условие | Стадия A | Стадия B |
|---|---|---|
| B0_control | нет | stock → наш train, 1700 updates |
| C1_matched_budget | stock → наш train, 850 updates | перенос backbone/BNNeck → наш train, 1700 updates |
| E1_nive_transfer | stock → NiVe train, 850 updates | перенос backbone/BNNeck → наш train, 1700 updates |

Начальная точка всегда публичный stock, не локальный MVP. Архитектура для всех трёх:
OSNet-AIN x1.0, average pooling, BNNeck, 512D, вход 208 square, прежние CE/SupCon/consistency
и аугментации B0, P16×K2. Ни GeM, ни MixStyle в этом эксперименте не добавляются.

У C1 и E1 при переходе к стадии B одинаково:

- переносятся параметры backbone и BNNeck, включая running statistics;
- создаётся новый classifier для текущих target identity;
- создаётся новый optimizer без source momentum и заново начинается target LR schedule;
- backbone не замораживается; новые параметры и стратегии loss не добавляются.

Поэтому C1 — **двухэтапный дополнительный контроль**, а не обычный непрерывный training run
на 2550 шагов. Он контролирует дополнительные updates и reset между стадиями. C1/E1 имеют
одинаковые budgets/batch/sample presentations, но не гарантированно одинаковые wall time/FLOPs:
число source identity и стоимость чтения фотографий различаются. B0 здесь обучается заново;
старые checkpoint автоматически не объявляются совместимыми с новым trainer.

Стадия A всегда использует **последний фиксированный шаг 850**, без оценки holdout.
Стадия B primary/alternate использует лучший raw inner mAP@10, включая step 0.
LR horizon стадии B всегда 1700, в том числе при более коротком финальном refit.

## Защита разбиений

- Organizer CSV, bbox, vehicle_id/camera_id, исходные изображения и splits не редактируются.
  Ни один пример организаторов не удаляется. Существующие primary/alternate frame-grouped
  inner splits и outer protocols берутся из той же проверяемой процедуры, что в variant 14.
- C1 на primary предобучается только на primary train; на alternate — отдельно только
  на alternate train. Нельзя переносить его primary checkpoint в alternate: это утечка.
- E1 обучается только на `NiVe1303/train` (17 070 изображений, 703 identity).
  Одно NiVe-предобучение на seed переиспользуется между folds: оно не видит organizer holdout.
- `NiVe1303/test/query` и `test/gallery` (600 identity) проверяются на целостность и пересечения,
  но не входят в training loader, выбор checkpoint, loss или подбор бюджета.
- `_MK_PURE` не читается. В локальной копии `train_MK_PURE` содержит 5049 масок фотографий
  внешнего test; это не источник определения training split.
- Identity NiVe имеют отдельное пространство имён `nive:<id>`. Пути сохраняются напрямую,
  без копирования фотографий и без искусственной правки bbox. Фото NiVe — готовые 256×256 crop.
- EN/ES/N/S в имени — только proxy ракурса для PK-sampling. Это **не подтверждённая карта
  физических камер**. Время/имена/метаданные не подаются модели и не участвуют в inference.
- Проверка SHA256 обнаруживает точные совпадения, но не гарантирует отсутствие near-duplicates.
  `Image.verify()` проверяет структуру/заголовки; изображения декодируются загрузчиком при чтении.

## Confirmation и финальная оценка

1. Все три условия на трёх фиксированных primary seed, включая результаты пилота.
2. Freeze победителя по среднему primary raw mAP@10 и медианы best target step для каждого условия.
   Сохраняются paired-seed разности E1−B0 и E1−C1; это три seed, не достаточная выборка для сильных гарантий.
3. Все три условия на трёх alternate seed. Этот split не меняет победителя/число refit steps.
4. Final refit всех трёх на исходном outer train и первом seed, без оценки во время обучения.
   У C1 source-стадия заново учится на полном outer train; у E1 source остаётся NiVe train.
   Source budget по-прежнему 850, target budget — замороженная медиана.
5. Все final checkpoint фиксируются до первой outer оценки. Пороги выбираются только на
   исходной calibration и используются неизменными для original/masked diagnostics.
6. Прежний fixed rerank k1=20, k2=3, lambda=.5; per-query bootstrap E1 против B0 и C1.
   ONNX-export — только в experiment run, проверка batch 1/3/8 и L2-нормы.

`RESULTS.md` содержит original/masked mAP@10, F1, TNR и замороженный MVP reference.
Детальные candidate metrics доступны в `final/*/seed_*/evaluation.json`.
Validation уже исследовалась ранее: это development, не независимый финальный тест.
Bootstrap условен на фиксированной gallery. Автоматического продвижения в MVP нет.
Отдельный night/day-срез не реализован без заранее проверенной разметки освещения.

## Источник и ограничения

- [NiVe1303 v1](https://data.mendeley.com/datasets/42wv2svztx/1), Ruozheng LI,
  DOI **10.17632/42wv2svztx.1**, опубликован 14 сентября 2026.
- Лицензия на официальной странице: **CC BY 4.0**. Автор/ссылка/версия должны сохраняться
  в документации решения с указанием преобразований (resize/нормализация/аугментации в памяти).
- Публичная карточка не доказывает происхождение конкретной локальной копии: поэтому есть
  отдельное подтверждение пользователя. Исходного архива нет, его SHA256 не выдумывается;
  manifest фиксирует хеш каждого из 31 735 JPEG и fingerprint всего списка.
- Организаторы разрешают публичное воспроизводимое предобучение и не требуют обязательного
  маскирования номеров во внешнем train (ORGANIZER_QA.md, вопросы 17 и 49). NiVe описывает
  номера как неразличимые из-за motion blur; это не гарантия специальной маскировки каждого кадра.
  OCR/номерные признаки не используются. Наш original/masked контроль остаётся обязательной диагностикой.
- NiVe содержит только ночные снимки: возможна отрицательная адаптация к этому домену.
  Улучшение на NiVe не считается успехом; важны наши inner и итоговые метрики.
- Смешанные batches, обучение по маскам частей и архитектурные изменения — отдельный следующий этап,
  не скрытые опции этого notebook. Ни новый датасет, ни веса не скачиваются автоматически.

## Артефакты

`runs/<RUN_NAME>/manifest.json` фиксирует источники, bytes/protocol fingerprints, бюджеты и runtime.
`pretrain/nive/E1_nive_transfer` — общие source checkpoint; `pretrain/<fold>/C1_matched_budget` —
раздельные target-only source checkpoint. `primary`, `alternate`, `final` — стадии B.
В каждой папке: authoritative `last.pt`, `best.pt`, `history.json`, `summary.json`.
Результаты pilot и confirm записываются раздельно, повторный pilot не стирает отчёт confirm.

Модули: `training/nive_transfer.py`; проверки: `tests/test_nive_transfer.py`.
