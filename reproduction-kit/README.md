# Исходники для воспроизведения MVP_fusion_v25

Комплект фиксирует **четыре обученных компонента действующего v25** и код,
который объединяет их при поиске. Он не включает варианты 41/42 и не меняет
работающий сервис. Это этап подготовки исходников; конкурсные CSV, embeddings,
образ Docker и презентация готовятся отдельно.

## Состав

| Путь | Назначение |
| --- | --- |
| `run_selected.py` | Обучение уже выбранных рецептов и экспорт ONNX |
| `source/` | 83 исторических файла из коммита `8fc310ca6ac1d8467ef8bfdc5ce4c1d1afa4498b`; код не изменён |
| `metadata/recipe.json` | Связь рецептов, checkpoint, ONNX и профиля v25; SHA256 |
| `metadata/splits.json` | Identity-разбиение, query/gallery протоколы и хеши исходных кадров |
| `metadata/*summary.json`, `*export.json`, `*bundle.json` | Сохранённые сведения о выбранных моделях, не новые результаты |
| `runtime/` | Код inference и настройки из main `91d559c2e0024fd117f74943781b6b9ee84c997d` |
| `requirements.txt` | Зависимости запуска с ограничениями из исторического lock-файла |
| `verify.py`, `KIT_SHA256.json` | Проверка целостности исходников и данных |
| `pack.py` | Сборка ZIP только из файлов, перечисленных в манифесте |
| `VALIDATION.md`, `evidence/` | Выполненные проверки и их границы |

**Датасета с изображениями здесь нет.** Нет также обученных `.pt`, готовых четырёх
ONNX и результатов новых экспериментов. Их контрольные суммы сохранены.
Stock ONNX для инициализации включён в отдельный ZIP (8,8 МБ); в Git второй экземпляр
этого файла игнорируется, поскольку он уже есть в корневом `models/` продукта.
Лицензия stock-модели MIT: `source/models/LICENSE.osnet`; происхождение и URL —
`source/models/README.md`. Лицензии исторически включённого стороннего кода сохранены
рядом с ним. Наличие кода CLIP/NiVe/масок в историческом снимке не означает его
использование выбранными четырьмя рецептами.

## Подготовка

Референсная среда обучения: Python **3.11.9**, macOS/MPS, PyTorch 2.14.0,
torchvision 0.29.0. Проверки этого комплекта выполнялись на CPU macOS.
Команды обучения рассчитаны на macOS/Linux: исторические обучающие модули
импортируют `fcntl`. Это ограничение исходников обучения, а не inference.

Распакуйте ZIP или откройте папку `reproduction-kit` в репозитории.
При работе из Git один раз скопируйте уже имеющийся stock ONNX:

```bash
cp ../models/osnet_ain_x1_0_vehicle_reid.onnx source/models/
```

В ZIP он уже есть. Команды ниже выполняются из корня комплекта:

```bash
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python verify.py
python run_selected.py preflight --dataset /path/to/organizer-dataset
```

Папку датасета предоставляет пользователь:

```text
/path/to/organizer-dataset/
  train.csv
  images/
    <image_id>.jpg
```

Используется исходная размеченная часть организаторов: **9556 объектов**,
925 train / 307 calibration / 309 validation identity. В обучение попадают
5717 объектов из 925 train identity. Совпадения исходных кадров не переходят
между частями. Проверка заново читает SHA256 всех 9556 файлов (9547 уникальных
содержимых) и сравнивает `train.csv`. Test query/gallery для обучения,
предобучения, выбора настроек и калибровки не читаются.

Preflight проверяет также восстановление исходного порядка query/gallery.
Проверка целостности `verify.py` работает без ML-библиотек; `run_selected.py
preflight` дополнительно загружает код и проверяет протоколы.

## Воспроизведение выбранных компонентов

| Компонент | Размер входа | Seed | Остановка | Горизонт learning rate |
| --- | --- | --- | --- | --- |
| legacy | 208×208 | 20260915 | Эпоха 5 | **30 эпох** |
| r1_20260915 | 256×256 | 20260915 | Шаг 800 | **1700 шагов** |
| r1_20260916 | 256×256 | 20260916 | Шаг 800 | **1700 шагов** |
| r1_20260917 | 256×256 | 20260917 | Шаг 800 | **1700 шагов** |

Запускайте последовательно в новых папках. Ни одна команда не запускается
автоматически при распаковке, проверке или импорте:

```bash
python run_selected.py train --member legacy --device mps --dataset /path/to/organizer-dataset --output runs/legacy
python run_selected.py train --member r1_20260915 --device mps --dataset /path/to/organizer-dataset --output runs/r1_20260915
python run_selected.py train --member r1_20260916 --device mps --dataset /path/to/organizer-dataset --output runs/r1_20260916
python run_selected.py train --member r1_20260917 --device mps --dataset /path/to/organizer-dataset --output runs/r1_20260917
```

Для другого устройства укажите `cpu` или `cuda`. Запуск требует
несуществующую папку `--output` и отказывается писать внутрь датасета или
исторического `source/`. Возобновление незавершённого запуска через этот CLI
не предусмотрено: используйте новое имя. Существующие результаты не удаляются.

В каждом `runs/<member>/` появятся `run.json`, `encoder.onnx`, `export.json` и
checkpoint/история обучения. Legacy сохраняет `last.pt` эпохи 5; R1 —
`final/R1_resolution256/seed_<seed>/step_00800.pt`.
После обучения автоматически выполняется CPU-проверка PyTorch→ONNX на реальных
кропах с batch 1, 3 и 8. Новые веса **не устанавливаются в продукт**.

`run_selected.py` не повторяет поиск Optuna, перебор абляций или выбор победителя.
Он воспроизводит **зафиксированный рецепт**. Legacy повторяет первые пять эпох
`training.hpo.fit_selected`, сохраняя 30-эпоховое расписание и обе оценки между
эпохами, чтобы не менять случайное состояние DataLoader. R1 вызывает исходную
`training.osnet_review_protocol.fit` с `fold=final`, шагом 800 и исходными
границами 200/285/400/600/800. Маски и промежуточные результаты HPO ему не нужны.
Все аугментации, BNNeck, loss, PK sampling и optimizer остаются историческими.

## Экспорт имеющегося checkpoint без обучения

```bash
python run_selected.py export --member legacy --dataset /path/to/organizer-dataset --checkpoint /path/to/best_map.pt --output runs/export_legacy
python run_selected.py export --member r1_20260915 --dataset /path/to/organizer-dataset --checkpoint /path/to/step_00800.pt --output runs/export_r1_20260915
```

Для двух остальных R1 укажите их member и соответствующий checkpoint. Проверяется
эпоха/config legacy или подпись seed/рецепта/разбиения R1. Загружаются только
checkpoint собственной модели через `weights_only=True`. `export.json` содержит
SHA256, проверку численных выходов и признак побайтового совпадения с эталоном.

## Связь с конечным v25

В `runtime/models/profiles.json` и frozen bundles сохранены пути и контрольные
суммы исходных четырёх ONNX. Legacy выдаёт 512 признаков; три нормированных
R1-вектора объединяются с равными весами в 1536 признаков. Итоговый формат —
2048 признаков с нормировкой блоков, без общей перенормировки.

Порядок результатов: смесь cosine legacy/R1 **50/50**, затем streaming
k-reciprocal, `k1=20`, `k2=3`, `lambda=0.5`. Кандидат и отказ считаются отдельно
по raw cosine ансамбля R1; эталонный порог **0.534365177154541**. Код этого пути
находится в `runtime/backend/{dual_role,frozen_encoder,runtime,rerank}.py`.
Запросы обрабатываются независимо относительно статичной gallery.

`runtime/` — снимок кода и конфигурации, а не готовый сервер без весов. Для
воспроизведения текущего inference возьмите неизменённые ONNX из `models/`
указанного main-коммита, сохранив относительные пути. Для повторно обученных
весов требуется отдельная оценка на сохранённых протоколах и калибровка на
calibration; автоматически применять к ним старый порог и старые SHA нельзя.
Подмена действующей системы не входит в этот комплект.

Первоначальный legacy checkpoint и рецепт уже выбирались с использованием
development validation; опубликованные метрики не являются независимым тестом.
Битовая идентичность нового обучения на другом устройстве не обещается.
Полный исторический поиск описан в сохранённых notebook/README; для него нужны
дополнительные промежуточные стадии. Рекомендуемая точка входа этого комплекта —
`run_selected.py`, а не Run All исторических notebook.

## Проверки и упаковка

```bash
python -m unittest discover -s tests -v
python pack.py --output /path/to/vehicle-reid-v25-reproduction.zip
```

ZIP включает только перечисленные в `KIT_SHA256.json` файлы. Ни соседний датасет,
ни `.venv`, ни `runs/`, ни файлы сдачи туда не попадают. Рядом создаётся файл
`.zip.sha256`. Смена будущей модели 41/42 требует нового комплекта с её рецептом
и новой связью checkpoint→ONNX; этот снимок v25 остаётся самостоятельным.
