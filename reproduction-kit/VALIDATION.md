# Проверка комплекта, 28 сентября 2026

Проверена переносимость исходников и экспорт выбранных моделей. **Полное
обучение четырёх моделей заново не выполнялось**.

## Что подтверждено

- Все 83 файла `source/SOURCE_SHA256.json` совпадают с зафиксированным архивом.
  Исходники, перечисленные в manifest вариантов 16/17 во время их обучения,
  тоже совпадают с сохранёнными тогда SHA256.
- Проверены исходный `train.csv` и 9556 изображений (9547 уникальных SHA256).
  Разбиение — 925/307/309 identity; утечки одинаковых identity/кадров между
  частями не обнаружены. Порядок calibration/validation query/gallery
  восстанавливается исходным кодом без изменений.
- Шесть автоматических тестов проходят. Они проверяют отбрасывание изменённых
  изображений/разметки и утечки одинакового кадра, а также совпадение первых
  пяти эпох нового запуска legacy с историческим 30-эпоховым драйвером на
  малой контрольной модели. Последний тест использует настоящий optimizer/RNG,
  но не заменяет полное обучение OSNet.
- Все четыре существующих checkpoint загружены через новый CLI и повторно
  экспортированы на CPU. PyTorch→ONNX проверен на реальных кропах с batch 1/3/8.
  Три R1 ONNX побайтово совпали с действующими файлами.
- У legacy все **265 initializer tensors совпадают точно**. Единственное
  отличие графа — имя области `GlobalAveragePool` стало
  `global_pool/GlobalAveragePool` в более позднем сохранённом исходнике.
  После унификации этого имени графы совпадают; выходы исходного и нового ONNX
  на batch 1/3/8 совпали точно. Новый SHA256 отличается: это не объявляется
  побайтовым воспроизведением legacy ONNX и не используется для его подмены.
- Комплект распакован в отдельную временную папку. Оттуда успешно выполнены
  preflight с исходным датасетом и все шесть тестов; исследовательские исходники
  не использовались. В архиве нет изображений, CSV, `.pt`, `.npy`, окружения
  или Python-кэшей. Единственный ONNX — stock-инициализация.

## Ограничения

Проверки выполнялись в уже установленной среде Python 3.11.9 на macOS arm64,
PyTorch 2.14.0, ONNX 1.22.0, ONNX Runtime 1.30.0. Новая установка зависимостей
с нуля не выполнялась. Lock исторического notebook-окружения
сохранён; облегченному CLI достаточно зависимостей из корневого `requirements.txt`.

Пакет воспроизводит зафиксированные рецепты, а не заново доказывает правильность
исторического выбора. Исходный legacy выбирался по development validation.
Нельзя обещать те же веса/метрики после повторного обучения на другом устройстве.
Полученные заново веса требуют своей проверки и калибровки, прежде чем менять
работающий v25. Конкурсные артефакты, публикация и смена модели сюда не входят.
