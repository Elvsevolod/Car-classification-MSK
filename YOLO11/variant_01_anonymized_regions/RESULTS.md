## Калибровка масок — 21.09.2026

`training/mask_calibration.py`, новый [ноутбук](calibrate_yolo11_masks.ipynb).
Использованы прежние `best.pt` и ручной эталон, без обучения и без новых данных.
На CPU сделан один проход **только по 40 val-кропам** с confidence 0.05.
Сохранены неокруглённые рамки после NMS, перебраны 49 конфигураций:

- Confidence: 0.05, 0.10, 0.15, 0.20, 0.25, 0.35, 0.50.
- Margin с каждой стороны: 0, 0.03, 0.05, 0.075, 0.10, 0.15, 0.20.
- Ограничения до подбора: лишняя площадь ≤3% всей площади и ≤10% отдельного кропа.
- Выбор — максимум областей, покрытых ≥90%, затем покрытой площади, затем минимум
  лишней площади; при равенстве выше confidence и меньше margin.

Выбраны и сохранены **confidence 0.20, margin 0.10**. Исходный baseline 0.25/0.0
из нового кэша совпал по всем исходным показателям покрытия с предыдущим отчётом.

| Показатель на validation | Baseline 0.25 / 0 | Calibrated 0.20 / 0.10 |
|---|---:|---:|
| Покрытие площади ручных масок | 84.11% | **91.51%** |
| Областей с покрытием ≥90% | 30 / 49 | **43 / 49** |
| Кропов, где все области покрыты ≥90% | 21 / 40 | **34 / 40** |
| Полностью пропущенных областей | 3 | **2** |
| Лишняя площадь от всей площади кропов | 0.97% | **2.98%** |
| Максимальная лишняя площадь одного кропа | 6.55% | **9.60%** |
| Предсказанных рамок | 51 | 53 |
| Доля лишних пикселей в предсказанных масках | 18.16% | 38.43% |
| F1 сопоставления расширенных рамок при IoU ≥0.5 | 0.8600 | 0.7451 |

Улучшение покрытия достигается ценой более широких масок, а не улучшением точности
детектора. После расширения F1 рамок падает: это **не** новый detector mAP и не
доказательство улучшения ReID. Порог 90% не гарантирует полной непрозрачной маски.
Большие и краевые области всё ещё могут закрываться не полностью. Отрицательных
кадров нет, частота ложных масок на чистых кадрах неизвестна.

Результаты: `runs/pilot_01/calibration_v1/raw_val.json`, `calibration.json`.
Второй файл содержит все 49 вариантов, выбранные настройки, сводные и покадровые
метрики, предсказания baseline/calibrated и хеши входов/кода. Эти результаты не
перезаписываются при обычном повторном Run All. Holdout-файлы пока не созданы.
