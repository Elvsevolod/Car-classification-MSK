## Подбор параметров после обучения

- Модуль `training/mask_calibration.py`, 49 сочетаний confidence/margin на **val**.
- Один проход по 40 val-кропам при confidence 0.05; сохраняются float xyxy после
  NMS (IoU 0.45). Более высокие пороги фильтруют этот кэш; расширение делается до
  округления наружу. Начальная конфигурация для сравнения: 0.25 / 0.0.
- Максимум лишней площади: 3% от всех кропов и 10% любого отдельного кропа.
  Это заранее заданные эвристики пилота, не требования организаторов.
- Выбор: максимум областей с покрытием ≥90%, затем максимум покрытой площади,
  затем минимум лишней площади. При равенстве — более высокий confidence и меньший margin.
  Если допустимых вариантов нет, holdout не открывается.
- Папка `runs/pilot_01/calibration_v1/`: `raw_val.json`, `calibration.json`.
  Результаты содержат хеши весов, разметки, плана, кода и настройки inference.
  Готовая калибровка переиспользуется, а не пересчитывается по новому устройству.
- `RUN_HOLDOUT=True`: только два заранее заданных варианта — baseline и frozen
  calibrated. Создаются `raw_holdout.json`, `holdout_final.json`; настройки из
  holdout не выбираются. Это оценка покрытия, не новый расчёт detector mAP.
- Повторный Run All читает готовый результат. При прерывании сохраняются уже
  обработанные кадры; продолжение — на том же устройстве. При изменении входных
  данных/кода несовместимые результаты не перезаписываются.
- После просмотра holdout нельзя подгонять настройки под него или удалять его
  результаты ради повторной «независимой» оценки. Следующий отдельный этап —
  сравнение ReID без масок / с фиксированными автоматическими масками.

Калибровка выполнена локально на CPU; baseline совпал с ранее сохранённой MPS-оценкой.
Само обучение было на MPS. Новый проход holdout выберет доступный MPS/CUDA, иначе CPU,
и сохранит фактическое устройство. Дополнительных зависимостей/скачиваний не нужно.

## Как выполнялась разметка (для справки)

Открыть [разметчик](annotation/annotate_masks.html). Он работает локально без сервера.
Это **новые 240 кропов**, не прежние 126. Начальные рамки уже подставлены для
обучения и validation, но ни одна не считается проверенной.

1. Сверить зелёный BBox организаторов на полном кадре; размечать только правый кроп.
2. Исправить красные рамки: удалить ошибочную отдельной кнопкой и нарисовать новую.
   Добавить пропущенные области. «Отменить изменение» отменяет последнее действие.
3. Выделять **все искусственно анонимизированные области внутри кропа**, включая
   края размытия, обрезанные краем кропа участки и области соседних автомобилей.
   Не выделять естественную нерезкость, блики, тени и предполагаемое место номера.
   Раздельные участки — отдельные прямоугольники без лишних деталей между ними.
4. Нажать **«Проверено»**. Если областей действительно нет, оставить пустой список
   и также подтвердить проверку. Отсутствие подсказки НЕ означает отсутствие области.
5. Для последних 40 кропов подсказок нет: это самостоятельная контрольная разметка.
6. Каждые 20–30 кадров скачивать JSON. Финальный файл должен содержать 240/240
   проверенных записей. При возобновлении его можно загрузить обратно в разметчик.

Имя выгрузки: `yolo11-masks-2eced57f.json`. Браузер может добавить `(1)` и т. п.
Пришлите этот файл для проверки или сохраните копию как
`annotation/reviewed_masks.json` и задайте путь в ноутбуке.
Старый `masks-7.json` сюда загружать не надо: другой fingerprint, другой набор.

Разметчик хранит JSON в localStorage под отдельным ключом набора, но это лишь
страховка: скачанный файл обязателен. Исходные фотографии интерфейс не меняет.
Предложения можно отдельно заменить на DeepMosaics или YOLO11n, однако это
сбрасывает отметку проверки текущего кадра. В контрольной части эта функция скрыта.

## Какие модели используются

Для **подсказок**: уже скачанные YOLO11n license-plate ONNX и DeepMosaics raw.
Их версии/контрольные суммы записаны в `annotation/proposals.json`. Перекрывающиеся
предложения YOLO с покрытием более 75% меньшей рамки не дублируются поверх DeepMosaics;
неперекрывающиеся добавляются. Это удобство интерфейса, не новый проверенный ансамбль.
Предложения на holdout вообще не генерировались.

Для **обучения**: официальный **Ultralytics YOLO11n, COCO pretrained `.pt`**,
а не прежний сторонний ONNX-детектор номеров. Используем опубликованные стартовые
веса; сторонние обучающие фотографии не добавляем. Голова перестраивается под один
класс `anonymized_region`; обучается детекция всей области, не OCR или восстановление.

Источник: [Ultralytics assets v8.3.0](https://github.com/ultralytics/assets/releases/tag/v8.3.0),
автор Ultralytics. URL, SHA-256 и лицензия — [model.json](weights/pretrained/model.json).
По [официальной документации YOLO11](https://docs.ultralytics.com/models/yolo11/)
действуют AGPL-3.0 либо отдельная Enterprise-лицензия; условия поставки нужно соблюдать.
DeepMosaics не включается автоматически в итоговый продукт.

## Обучение

Ноутбук: [train_yolo11_masks.ipynb](train_yolo11_masks.ipynb).

- `RUN_TRAINING=False` по умолчанию. До подтверждения новой разметки обучение запрещено.
- 50 эпох максимум, patience 10, batch 8, размер 640, AdamW, LR 0.001,
  cosine schedule, weight decay 0.0005, warmup 3 эпохи.
- `device`: CUDA при наличии, иначе MPS, иначе CPU; устройство печатается явно.
  На этом Mac MPS доступен (Apple M4 Pro). AMP отключён, workers 0.
- Умеренные изменения масштаба/положения/цвета, горизонтальное отражение;
  Mosaic/MixUp/CopyPaste выключены. Синтетические замазки без bbox не добавляются.
- Seed зафиксирован, однако MPS предупреждает о недетерминированной операции
  `index_put_with_accumulate_mps`: побитное совпадение повторных запусков не обещаем.
- Веса `best.pt` выбираются по validation mAP@0.5:0.95 (fitness в закреплённой версии).
  Сохраняется также `last.pt`; все промежуточные эпохи не копируются для экономии места.
- `epoch_times.json`: длительность обучения+validation каждой эпохи, метрики.
  В консоли — текущая эпоха, оставшиеся эпохи, ETA до максимального лимита.
- Для прерванного запуска `RESUME=True`, тот же RUN_NAME/JSON/config. Для завершённого
  или не успевшего сохранить первую эпоху — новое имя, без удаления прошлых результатов.
- JSON → YOLO: координаты кропа xyxy преобразуются в нормированные cx/cy/w/h.
  Обучающие PNG сохраняются из оригинального кропа без перерисованных рамок.
  Пустой label допустим только после ручной отметки проверки.
- `data.yaml` содержит только train/val; отдельный `holdout.yaml` подключается явно.
  При изменении JSON нельзя незаметно перезаписать существующий экспорт/эксперимент.

После обучения: стандартный bbox mAP и оценка масок на val — покрытие площади,
области с покрытием ≥90%, лишняя площадь, ложные маски на отрицательных кадрах.
Стандартный mAP оценивает исходные рамки детектора, а покрытие — заданный confidence
и margin. Подбор порога/запаса только на val, каждый вариант в отдельную папку.
`RUN_HOLDOUT=False` до окончательного выбора. Проверка влияния на ReID — следующий
отдельный эксперимент; этот ноутбук не меняет MVP и не считает улучшение ReID доказанным.

## Локальное окружение и воспроизведение

`ultralytics==8.3.241` и дополнительные пакеты закреплены в
[requirements-runtime.txt](requirements-runtime.txt). Они изолированы в
`artifacts/yolo11_runtime`; OpenCV уже был в `artifacts/mask_detector_runtime`.
Основные torch/torchvision/numpy и исходные обучающие ноутбуки не обновлялись.
Настройки Ultralytics находятся в `artifacts/yolo11_settings`, синхронизация и
внешние логгеры выключены. Изображения никуда не загружаются.

Команды из корня репозитория:

```sh
uv pip install --python .venv/bin/python --target artifacts/yolo11_runtime --cache-dir .uv-cache --no-deps -r YOLO11/variant_01_anonymized_regions/requirements-runtime.txt
PYTHONPATH=artifacts/mask_detector_runtime .venv/bin/python -m training.mask_finetune prepare --output YOLO11/variant_01_anonymized_regions/annotation_new
PYTHONPATH=artifacts/mask_detector_runtime .venv/bin/python -m training.mask_finetune export /absolute/path/to/reviewed.json
PYTHONPATH=artifacts/mask_detector_runtime .venv/bin/python -m pytest -q
```

На новом checkout сначала нужны исходные CSV/фотографии, существующий ReID split
и модели подсказок из двух прежних экспериментов. Сам ноутбук после готовой
разметки не требует DeepMosaics. Официальные стартовые веса YOLO11 скачиваются
по URL из manifest; SHA-256 проверяется перед загрузкой. Для нового набора создаётся
отдельная папка: старые JSON автоматически не удаляются и не переиспользуются.

Результаты обучения появятся в `runs/<RUN_NAME>/`. PNG-экспорт, HTML с фотографиями,
бинарные веса и runs исключены из Git. Код, ноутбук, планы и provenance сохраняются.

API сверены с [Train/MPS/resume](https://docs.ultralytics.com/modes/train/),
[YOLO format](https://docs.ultralytics.com/datasets/detect/) и
[callbacks](https://docs.ultralytics.com/usage/callbacks/); фактическое поведение
проверяется на закреплённом локальном пакете, а не только по текущей документации.
