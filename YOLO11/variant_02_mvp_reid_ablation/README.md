# Автоматические маски и основная модель MVP

Парный эксперимент **без обучения и без изменения MVP**. Сравнивается текущая
OSNet-AIN x1.0 / HPO best-mAP epoch 5 в ONNX: исходный кроп против того же кропа
после непрозрачного чёрного закрашивания областей, найденных дообученным YOLO11n.

## Результат запуска 2026-09-21

Эксперимент завершён. mAP@10 с реранкингом снизился с **81.47% до 77.66%**,
Rank-1 — с **80.16% до 76.11%**. Исходный baseline воспроизведён;
MVP, веса, индекс и порог оставлены без изменений. Маски не включены в продукт.
Подробности, ограничения и следующий возможный эксперимент — в [RESULTS.md](RESULTS.md).

## Зафиксированный протокол

- Полная существующая outer validation: 309 query / 896 gallery из train.csv.
  247 запросов имеют cross-camera пару; 62 — искусственный open-set без пары.
- Одинаковые query/gallery и порядок в обеих версиях. Маски применяются **к обеим
  сторонам**, до исходного bilinear resize 208×208, ImageNet-нормализации и L2.
- Та же ONNX-модель, CPUExecutionProvider, без TTA. Реранкинг streaming k-reciprocal
  20 / 3 / 0.5, порог отказа 0.5948754549026489 по максимуму исходного cosine.
- Отдельно считаются raw и reranked показатели, официальным `evaluate.py` через
  существующие адаптеры backend. Выход top-10, junk/open-set — как в MVP-протоколе.
- YOLO: прежний `variant_01_anonymized_regions/runs/pilot_01/weights/best.pt`.
  Confidence 0.20 и margin 0.10 читаются из сохранённой validation-калибровки,
  а не подбираются по ReID. Новый детектор или сторонние данные не добавляются.
- Проверяются хеши весов, исходных фотографий/CSV, кода, разделение идентичностей
  и точных кадров. Все 240 detector train/val/holdout кропов должны быть вне ReID
  validation по кадрам и целевым идентичностям.

## Запуск из корня репозитория

```sh
PYTHONPATH=artifacts/mask_detector_runtime .venv/bin/python -m training.mask_reid_ablation --device cpu
```

Если не задавать `--device`, для YOLO автоматически выбирается доступное устройство.
ReID всегда использует **тот же ONNX CPU encoder, что и MVP**. Это проверка качества,
не замер скорости на стенде организаторов.

Модуль `training/mask_reid_ablation.py`. Выходы — `runs/paired_v1/`:

- `experiment.json`: фиксированный протокол, конфигурация и контрольные суммы.
- `paired_embeddings.npz`: обе матрицы эмбеддингов и автоматические рамки в
  координатах кропа. Сохраняется каждые 64 кропа, продолжение после прерывания.
- `comparison.json`: официальные метрики, покадровые решения, изменения Top-1/AP,
  парный bootstrap по запросам, контроль воспроизведения исходного baseline.

Повторный запуск переиспользует совместимые результаты. Смена входов/настроек
требует новой папки; старые кэши не заменяются молча. Фотографии, индекс gallery,
MVP embeddings/submission/candidates, пороги, старые отчёты и веса не меняются.
Большие кэши в `runs/` уже исключены из Git.

## Как интерпретировать

Это не новый независимый тест OSNet: этот development checkpoint ранее выбирался
по той же outer validation. Смысл — **парное изменение от добавления масок** при
неизменности остальных параметров. 95% bootstrap-интервал условен на фиксированной
галерее и не описывает неопределённость обучения/новых камер/скрытого теста.

Порог отказа не перенастраивается под замаскированные изображения: измеряется
добавление маскирования к существующему MVP. Если распределение cosine изменится,
это может отдельно повлиять на отказы. Это нельзя исправлять подбором по validation.
Полная независимость от номера/рисунка анонимизации этим экспериментом не доказана.
Полезность перед включением масок в продукт оценивается по mAP@10, Rank-1, F1 и TNR,
а не только по качеству детектора. Автоматического переключения MVP нет.
