# Архитектура Vehicle ReID

Профиль `MVP_fusion_v25` получает изображение и BBox, извлекает 2048 признаков четырьмя OSNet-моделями и независимо рассчитывает ranking и отказ.

## Модули

| Слой | Файлы | Назначение |
| --- | --- | --- |
| HTTP/API | `backend/app.py` | Загрузка изображений, параметры поиска, JSON-ответы, OpenAPI и локальный Swagger |
| Подготовка изображения | `backend/core.py` | Проверка изображения/BBox, EXIF, RGB, кроп и legacy-энкодер |
| Модели и профиль | `backend/frozen_encoder.py`, `backend/dual_role.py`, `backend/runtime.py` | Загрузка ONNX, проверка хешей, блоки legacy/R1 и настройки v25 |
| Поиск | `backend/runtime.py`, `backend/rerank.py` | Точный поиск, граф gallery, порядок результатов и отдельный R1-кандидат |
| Хранилище демо | `backend/cache_spaces.py`, `backend/postgres_gallery_repository.py`, `alembic/` | PostgreSQL + pgvector, изолированные пространства кэша и совместимость с моделью |
| Пакетный экспорт | `backend/infer.py`, `backend/runtime.py` | Три конкурсных файла без web/БД и контроль форматов |
| Интерфейс | `web-ui/` | React, просмотр кропов, ввод BBox, ranking и результат отказа |
| Поставка | `Dockerfile`, Compose-файлы | Сборка UI, CPU/GPU-окружение, миграции и запуск |

## Один запрос

1. Прочитать изображение, проверить BBox и получить кроп.
2. Подготовить общий кроп в размерах 208 и 256; извлечь legacy-вектор 512D и три R1-вектора по 512D. Подготовленный R1-batch используется всеми тремя R1-моделями.
3. Получить два нормированных блока: legacy512 и R1_1536.
4. Для ranking смешать cosine legacy/R1 поровну и применить k-reciprocal 20/3/0.5.
5. Для кандидата найти максимум raw R1 cosine и сравнить с порогом 0.534365177154541.
6. Вернуть top-10 и отдельное решение о совпадении.

Состав других query не участвует в этом процессе. Галерея фиксируется на запуск; запросы не добавляются в неё. Метаданные камеры, времени и местоположения не используются.

## Хранение и режимы

Веб-приложение сохраняет gallery в PostgreSQL с pgvector. Общий runtime выполняет полный поиск по её векторам; приближённый индекс для этой версии не заявляется. Кэш связан с хешами изображений, BBox, моделью и provider.

Batch хранит gallery в памяти процесса и использует тот же scorer. Ему не нужны БД, миграции, `train.csv` или отдельная калибровка. Порог v25 и связи моделей берутся из профиля и frozen bundle; legacy-файл `models/calibration.json` не задаёт порог v25.

Docker собирает React из `web-ui/` и отдаёт готовые ресурсы через FastAPI. Код старого интерфейса в `frontend/` сохраняется как fallback для запуска без сборки и отдельных тестов; он не является основной Docker-версией.
