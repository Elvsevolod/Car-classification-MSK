## Что реализовано

- Три frozen-профиля; общий runtime для приложения, экспорта и benchmark.
  Размерности 512/1536, отдельные политики ranking/candidate, собственные
  неизменные пороги. По умолчанию MVP/CPU; скрытый CUDA → CPU fallback запрещён.
- Изолированные атомарные PostgreSQL-кэши, проверка модели, preprocessing,
  порядка gallery, bbox и байтов изображений. Старые MVP-таблицы сохранены.
- Ранжированный results не исчезает при отказе. accepted_candidate показан
  отдельно с его фотографией и cosine, включая кандидата вне видимого top-K.
  Ручной порог интерфейса — только демо, конкурсный экспорт его не использует.
- JPEG/PNG и понятные ошибки отсутствующих/неоднозначных файлов. Никаких
  фиктивных векторов, пропусков изображений, OCR, детекции или обработки номеров.
- Автономная команда выдаёт submission.csv, candidates.csv и embeddings.npy;
  ей не нужны train, БД, UI, сеть или код обучения.
- Notebook verify_release_run_all.ipynb: последовательные проверки с
  прогрессом, временем и новым каталогом результата, без общего лимита времени.
  Полный проверочный прогон выполнен через тот же runner, который вызывает
  notebook; схема notebook и код его ячеек дополнительно проверены.

проверки интерфейса, а не пороги, допуски или решения модели.
