# main — продукт, fine-tuning — обучение

## main

Актуальное приложение с **MVP_fusion_v25**: API, React-интерфейс, PostgreSQL,
Docker и автономный трёхфайловый экспорт. Все четыре необходимые ONNX-веса
и прежние профили отката сохранены в `models/`.
Обучение, NiVe, train.csv и исследовательская рабочая копия для inference не нужны.
Размеченные/неразмеченные изображения организаторов пользователь добавляет отдельно.

Ветка включает `notebooks/verify_release_run_all.ipynb` — это проверка продукта,
не обучающий notebook. Расширенное сравнение с research в этом notebook требует
отдельной копии fine-tuning; обычный API/экспорт от неё не зависит.

## fine-tuning

[Обучающий код и эксперименты](https://github.com/Elvsevolod/Car-classification-MSK/tree/fine-tuning):
`training/`, семейства экспериментов, HPO, notebooks, протоколы и отчёты.
В `reproduction/` сохранён прежний пакет исходников legacy/R1 без изменения
зафиксированных SHA256 файлов `reproduction/source/`.
Точный коммит этого снимка указан в `BRANCH_PUBLICATION.md`.

Префикс `models/frozen/OSNet-AIN-x1.0/.../runs/...` в main сохраняет относительные
связи опубликованных моделей, а не полную историю исследований.
Новых train-checkpoint, optimizer-resume, NiVe и embedding-кэшей в main нет.
Незавершённые результаты текущей ночи не выдаются за зафиксированный результат.

## Правила дальнейшей работы

- Развивать готовое приложение от main, исследовательские гипотезы — от fine-tuning.
- Не переносить полную исследовательскую ветку в main. При одобренном улучшении
  переносить только frozen веса/профиль, необходимые inference-изменения, тесты и evidence.
- Не переключать/обновлять рабочие файлы под работающим notebook: его manifest
  проверяет входные файлы и исходники. Для продукта используйте отдельный checkout.
- История обеих веток сохранена; force-push не используется.
- Датасеты остаются локальными. Для полной сдачи обучающий исходный код можно передать
  отдельным архивом фиксированного коммита fine-tuning вместе с продуктовой сборкой.

Это организационное разделение, а не новый эксперимент или новая оценка качества.
Открытые ограничения сдачи из `release_decision.json` сохраняются.
