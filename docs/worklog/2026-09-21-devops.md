# Журнал devops — 21 сентября 2026

## Цель

Собрать воспроизводимый конкурсный runtime Vehicle ReID: FastAPI, PostgreSQL + pgvector, Docker Compose, офлайн-документация API, экспорт обязательных файлов и проверяемый запуск.

## Backend и данные

- Реализован FastAPI-контракт для health, query, изображений, embedding, поиска загруженного изображения и поиска official query.
- Поиск обрабатывает BBox по правилам API: проверка изображения и границ, crop, OSNet embedding, L2-normalization, pgvector exact cosine search, k-reciprocal reranking, confidence и отказ.
- PostgreSQL 16 + pgvector стали единственным runtime-хранилищем gallery.
- Добавлены Alembic-миграция, `PostgresGalleryRepository`, проверка fingerprint/хэшей и повторное использование gallery без ненужного пересчёта embedding.
- Для gallery из 750 объектов оставлен exact cosine search как воспроизводимый источник результатов; reranking работает поверх статичной gallery.

## Docker и offline runtime

- Подготовлены `Dockerfile`, `docker-compose.yml` и отдельный test compose.
- Runtime запускается non-root пользователем; dataset монтируется read-only; PostgreSQL и artifacts используют отдельные named volumes.
- Entrypoint ждёт healthcheck PostgreSQL, применяет Alembic-миграции и запускает FastAPI.
- Добавлены healthcheck API и profile `inference` для экспорта без веб-интерфейса.
- Offline Swagger UI использует файлы `frontend/vendor/swagger-ui/`, а не CDN.
- Документирован способ передачи жюри заранее собранных Linux `amd64` образов через `docker save`; после загрузки образов запуск выполняется без обращения в сеть.

## Экспорт и тестирование

- `backend.evaluate --export` создаёт и строго проверяет `submission.csv`, `embeddings.npy` и `candidates.csv`.
- Зафиксированы порядок query/gallery, float32 embeddings, Top-10, confidence и представление отказа без строк в candidates.
- Добавлены unit-, API-, format- и PostgreSQL/pgvector integration-тесты.
- Проверены Docker cold/warm startup, `GET /api/health`, API-сценарии, экспорт и offline Swagger.
- Итоги и воспроизводимые команды отражены в `README.md`, `docs/RUNBOOK.md` и `docs/TEST_SUMMARY.md`.

## Аудит требований

Выполнены: API, BBox → embedding → поиск → confidence/refusal, PostgreSQL + pgvector, Docker Compose, офлайн Swagger, экспорт обязательных файлов, документация и тестирование CPU-MVP.

Не закрыты и не должны заявляться выполненными:

- CUDA/GPU runtime и benchmark на RTX A5000 / CUDA 12.2;
- подготовленный и проверенный на чистом Linux `amd64` архив образов для жюри;
- презентация и сценарий защиты.

Подробная матрица находится в `docs/CONTEST_COMPLIANCE_AUDIT.md`.

## Результат

Ветка `devops` содержит функциональную и протестированную CPU-поставку проекта. Для запуска с исходниками и доступными образами используется `docker compose up --build`; для закрытого стенда без сети — заранее подготовленные и загруженные образы по `docs/CONTEST_IMAGE_DELIVERY.md`.
