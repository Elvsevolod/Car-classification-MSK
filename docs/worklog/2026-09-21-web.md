# Журнал web — 21 сентября 2026

## Цель

Подготовить демонстрационный веб-интерфейс Vehicle ReID без изменения FastAPI-контракта и сохранить его в production Docker-образе.

## Реализовано

- Создан отдельный React + TypeScript + Vite проект в `web-ui/`.
- Добавлены Tailwind CSS и локальные компоненты shadcn/ui (`Button`, `Card`): они входят в исходный код, не требуют CDN или интернета во время работы приложения.
- Реализована основная страница поиска:
  - проверка готовности модели и gallery;
  - загрузка JPEG/PNG;
  - выбор official query с поиском по части ID вместо списка из 1110 элементов;
  - получение изображения query и BBox из CSV через существующий API;
  - выбор BBox на canvas либо ручной ввод `x`, `y`, `w`, `h`;
  - режимы ranking/candidates, Top-K и ручной порог;
  - отправка изображения и BBox на `POST /api/search`;
  - скачивание JSON-ответа;
  - просмотр метрик и ссылок на offline Swagger/OpenAPI.
- Улучшено представление результата:
  - отдельный заметный блок «совпадение найдено» или «отказ»;
  - показ confidence и применённого порога;
  - карточки кандидатов с рангом, rerank, cosine, компактным ID и ссылкой на полный кадр;
  - длинные идентификаторы не ломают сетку карточек.
- Добавлена multi-stage Docker-сборка frontend на Node. В runtime-контейнер копируется только Vite `dist`; FastAPI раздаёт React из `frontend/dist`, а локальные assets Swagger остаются доступными по `/static/vendor`.
- README обновлён: теперь он описывает React/TypeScript/Tailwind интерфейс.

## Не менялось

- Публичный API `/api/*`.
- Логика OSNet, PostgreSQL + pgvector, reranking и refusal.
- Форматы конкурсных артефактов.

## Проверки

- `npm run build` — успешно.
- `npm run lint` — без ошибок; есть одно предупреждение Fast Refresh в сгенерированном shadcn-компоненте.
- `docker compose up -d --build --force-recreate vehicle-reid` — успешно.
- `GET /api/health` после старта — `ready`, `gallery_storage=PostgresGalleryRepository`, размер gallery 750.

## Результат

Ветка `web` содержит рабочий офлайн-интерфейс для сценария демонстрации: изображение + BBox → Top-10 либо отказ. Следующие улучшения, если понадобятся: browser smoke/e2e-тест интерфейса, подготовленные демонстрационные сценарии и презентация защиты.
