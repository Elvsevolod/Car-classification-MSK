## Что обнаружено и исправлено

- main уже содержит актуальный UI и утверждённый MVP_fusion_v25. Четыре активных
  ONNX лежат непосредственно в Git; все пять ONNX (включая stock) сохраняют байты
  origin/main. Исследовательские варианты v36–v38 не продвигаются автоматически.
- В исходном Docker был только CPU ONNX Runtime, не было GPU device reservation.
  Добавлен отдельный `docker-compose.gpu.yml` и точный GPU lock; CPU остаётся доступным.
- Выбран ONNX Runtime GPU 1.20.2, CUDA runtime 12.2, cuDNN 9.1 для заявленного
  организаторами драйвера CUDA 12.2. Все 43 зафиксированных Python-пакета доступны
  как Linux x86_64/Python 3.11 wheels; проверка требований их PyPI-метаданных
  не нашла отсутствующих или конфликтующих зависимостей.
- CUDA выполняет startup-пробы всех моделей с аудитом реальных ORT kernels.
  Допустим только служебный CPU `Shape`; CPU-вычисления сети или отсутствие CUDA
  завершают запуск ошибкой. FP32, TF32 выключен, cuDNN DEFAULT с ограничением workspace.
- Benchmark теперь явно вызывает `cudaDeviceSynchronize` до и после замеров,
  сохраняет информацию о GPU/драйвере и инвентарь весов. Добавлен psutil в runtime.
- Добавлено сравнение независимых экспортов: точные решения/порядок Top-10,
  кандидаты и отказы; точные embeddings по умолчанию либо явно заданный допуск.
- README исправлен под v25: порт 8017, 2048D, порог 0.534365177154541,
  отдельный R1-кандидат, raw cosine, сохранение ranking при отказе, запрет
  перезаписи результатов, offline-поставка с правильным тегом образа.
- Исправлено устаревшее ожидание legacy-порога в browser smoke. В Docker-тестах
  включены проверки профилей/отката PostgreSQL, ранее пропускавшиеся без
  `REID_TEST_DATABASE_URL`; используется разрешённое тестами имя одноразовой БД.

## Что ещё проверяет владелец RTX 4060

1. Успешная сборка и `preflight_passed=true`, GPU — RTX 4060, все четыре сети
   вычисляются CUDA; no-network режим работает.
2. Два полных экспорта на предоставленном наборе и точная повторяемость.
3. Сравнение CPU/CUDA: допуск vectors/confidence 2e-4, решения совпадают точно.
4. Benchmark: 50 прогревов, 300 latency-измерений; 1/8/16/32 не менее 10 секунд.
   Зафиксировать модель GPU (включая Laptop/Desktop), VRAM, драйвер, режим питания
   и фоновые нагрузки. Не пересчитывать результаты в «эквивалент A5000».
5. Web health показывает CUDA/v25/2048, работают загрузка/BBox, поиск, отказ,
   отдельный принятый кандидат, сравнение изображений и JSON.

VRAM измеряется периодическими NVML samples, а не точным пиком аллокатора.
В WSL process VRAM может быть недоступен; `null`/warning нельзя интерпретировать
как нулевое потребление или выполненный пункт требований. Это остаётся отдельной
проверкой на NVIDIA/Linux. Ошибки OOM/драйвера или различия решений сохраняются
в отчёте, не маскируются переходом на CPU или пересчётом threshold.

## Конкурсные ограничения

Обязательные форматы, потоковая независимость и методика измерения сверены с
`ORGANIZER_QA.md` (№8, 10, 11, 38, 43) и исходным PDF-ТЗ. Официальный `evaluate.py`
не менялся. В финальной сверке учтены [позднейшие уточнения чата](ORGANIZER_CLARIFICATIONS_2026-09-28.md):
требование `extractor.py` отменено 22.09.2026 (сообщение 349), поэтому оно снято
из открытых проверок. Вопрос junk/Top-10 сохраняется.

Остаются: контроль остаточного номерного сигнала, фактическая NVIDIA-приёмка,
презентация и ссылки на прототип/материалы. При передаче приложите фиксированный
обучающий код исследовательской ветки. `release_decision.json` сохраняет
`official_submission_ready=false`: подготовка инфраструктуры не закрывает эти пункты.

Совместимость проверялась по первичным источникам:

метаданные точных версий пакетов.
