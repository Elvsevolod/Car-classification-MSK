## Вывод

Интерфейс выполняет опубликованные функции демонстрационного сервиса. Основной CPU batch-пайплайн и контейнеризация работают, но полная конкурсная готовность ещё не подтверждена. Белый минималистичный интерфейс стоит развивать через удобство сравнения автомобилей и понятность доказательств, а не декоративные эффекты.

Q&A 44, 46 и 47 уточняют исходный PDF: обязательный минимум — автономная генерация трёх файлов одной командой, без обязательных БД/UI. Демо-интерфейс — дополнительный критерий при равенстве основных результатов, не самостоятельные дополнительные баллы. Качество демонстрации также может помочь объяснить решение на защите, но это не гарантированный прирост оценки. Представленный полный сервис должен запускаться одной командой и обходиться без интернета во время работы.

## Интерфейс: сверка с требованиями

| Требование / ограничение | Статус и основание |
|---|---|
| Загрузить JPEG/PNG и передать BBox | Выполнено: загрузка, выделение указателем, координаты в настройках и готовая разметка примера; `App.tsx`, `search-form.tsx` |
| Базовая валидация входа | Выполнено: тип/размер изображения, размерность, границы и положительный размер BBox; проверяется и сервером |
| Показать ранжирование и уверенность либо отказ | Выполнено: Top-N, фото кандидатов, raw cosine и порог, отдельные состояния ranking/accept/refusal; `search-results.tsx` |
| Не выдавать similarity за вероятность идентичности | Выполнено: явное пояснение, что raw cosine и rerank не являются вероятностями; принятие по порогу не называется подтверждённым совпадением |
| Экспорт результата демо | Выполнено: JSON текущего поиска. Конкурсные CSV/NPY создаёт отдельный batch-пайплайн; обязательного формата экспорта из UI организаторы не задали |
| Работа в стандартном браузере, документированный API | Выполнено: React тонкий клиент, FastAPI OpenAPI и локальный Swagger; формального теста фиксированной API-спецификации не будет (Q&A 47) |
| Автоматическая детекция / видео | Не требуется: Q&A 45 и 48 прямо задают статичный кадр и предоставленный BBox |
| Фиксированный frontend-stack | Не требуется: Q&A 46 разрешает свободный выбор. React/shadcn допустимы |
| Белая тема и адаптивность | Запрос команды, не условие ТЗ: проверены 390/768/1440 px, в том числе системная тёмная тема |

Не следует распространять этот вывод на старый source-only fallback `frontend/index.html`: это прежний тёмный интерфейс для запуска без собранного React. Docker и документированный локальный запуск после сборки используют текущий белый UI. Перед сдачей стоит исключить случайный показ fallback при демонстрации.

## Docker: что подтверждено

- `docker-compose.yml` и multi-stage `Dockerfile` собирают backend, локальные React/font/Swagger assets и модель. Python-зависимости закреплены версиями, frontend использует `npm ci` и lockfile.
- `inference` запускает `backend.infer` без PostgreSQL, миграций, `train.csv` и новой калибровки. Входной dataset монтируется только для чтения.
- Порог и проверяемые SHA/fingerprint входят в поставку модели. Общий размер включённых ONNX значительно меньше 2 ГБ.
- Для полного веб-сервиса есть одна Compose-команда, PostgreSQL healthcheck, автоматическая подготовка dataset-cache и непривилегированный web-процесс. Наружу публикуется только HTTP-порт, не PostgreSQL.
- Ранее выполненный полный offline batch с `--network none` и test-only dataset дал 1110 query / 750 gallery, корректные три файла и побайтное совпадение `submission.csv` с сохранённым MVP. Это историческое доказательство текущего backend, а не повторный запуск полного batch в этом аудите; подробности в [TEST_SUMMARY.md](TEST_SUMMARY.md).

## Docker: что пока не закрыто

1. **Целевая архитектура и оборудование.** Проверенный локальный образ — Linux ARM64/OrbStack, не Linux amd64. GPU-профиль и конкурсные замеры ещё не выполнены. CPU сам по себе не является доказанным нарушением формата, но его локальные показатели не подтверждают баллы на целевом стенде.
2. **Сетевая изоляция не включена по умолчанию.** В Compose нет `network_mode: none` для batch или изолированной внутренней сети для web/БД; живой bridge имеет `internal=false`. Приложение может работать без интернета, но стандартная команда сама исходящий доступ не запрещает. `--pull never` запрещает только загрузку образов. Для окончательной приёмки нужен запуск в реально изолированной сети; отсутствие ограничителя не означает, что приложение делает внешние запросы.
3. **Воспроизводимость обучения.** Исходники fine-tuning пока не включены в этот release-checkout: см. D-02 в отложенных замечаниях.
4. **Уточнение `extractor.py`.** Q&A 46 упоминает его контракт. Файла-адаптера в проекте нет, но точная сигнатура в предоставленных PDF/Q&A также отсутствует. Это открытый вопрос совместимости: запросить официальный пример/контракт, а не придумывать API и не объявлять несовместимость доказанной.
5. **Финальная передача образа.** Есть инструкция `docker save/load`, но итоговая поставка с контрольной суммой и проверкой на чистом целевом стенде ещё не зафиксирована. Публичный registry не является обязательным условием; архив допустим.

Дополнительная рекомендация по воспроизводимости: закрепить базовые образы по digest и итоговый образ по checksum. Сейчас `python:3.11-slim` — плавающий тег; это улучшение поставки, а не отдельно установленное нарушение ТЗ.

## Как сделать UI сильнее на демонстрации

Предложения ниже **не реализованы** в рамках этого аудита. Сохраняем белый фон, сдержанную типографику, локальные ресурсы и shadcn.

| Очерёдность | Улучшение | Зачем / критерий готовности |
|---|---|---|
| 1 | Сравнение «область исходного автомобиля ↔ кандидат» в одной панели с увеличением | Не приходится запоминать целый кадр и переключаться между вкладками. Оба crop видны одновременно, доступны полный кадр и клавиатурная навигация |
| 2 | Понятные примеры с миниатюрами | Вместо первых восьми хешей — легко выбрать пример; отдельно подготовить честные сценарии для защиты. Отказ должен быть реальным при фиксированном пороге, а не созданным ручным порогом `1` |
| 3 | Краткий блок mAP@10 / F1 / TNR вместо основного JSON | Сразу видны качество, размер validation и оговорка «локальная validation, не скрытый тест». Полный JSON остаётся в технических деталях |
| 4 | Удерживать исходный crop рядом с длинным Top-10 | Закреплённая компактная область на desktop; переход к результатам и возврат к исходнику на mobile |
| 5 | Меньше технического шума | ID, raw cosine и rerank — в подробностях; изображение и позиция кандидата — главные. Не вводить выдуманный «процент совпадения» |
| 6 | Доработать загрузку и обратную связь | Русская кнопка выбора файла вместо зависящего от языка браузера native label; ошибки BBox/файла рядом с исходником; время обозначить как обработку запроса, не конкурсный benchmark |

Отдельная дополнительная возможность ТЗ — настоящая интерпретируемость (Grad-CAM/Attention maps). Она потребует корректного метода и проверки: нельзя выдавать BBox, декоративную тепловую карту или ранжирование за объяснение внимания модели. На ближайший этап это менее выгодно по трудозатратам, чем качественное визуальное сравнение и разбор реальных ошибок.

Не добавлять ради внешнего эффекта карты камер, видео, аккаунты, автодетекцию, сложную анимацию или новый dashboard: это не решает текущую задачу оператора и не заменяет ML-качество/производительность.
